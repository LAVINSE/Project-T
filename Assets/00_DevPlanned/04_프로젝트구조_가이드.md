# 프로젝트 구조 가이드

수정일: 2026-09-22 · 기준: 변경-021·023·024·025, 공통 전투 화면·데이터 편집기·보상 기반

## 폴더와 네임스페이스

SWUtils처럼 기능·자산 종류별로 분리한다. `Defense`를 모든 기능의 상위 폴더나 네임스페이스로 사용하지 않는다.

| 위치 | 구분 | 내용 |
| --- | --- | --- |
| `Assets/02_Res/Animator` | 대상별 폴더 | 공방 등 Animator Controller와 Animation Clip |
| `Assets/02_Res/Data` | Common, Character, Enemy, Stage, Navigation, Pooling, Currency, Items | 공통 색상·아이콘, 캐릭터·적 통합 데이터, 스테이지, 경로, 풀 목록, 재화·아이템 정의 |
| `Assets/02_Res/Materials` | 표시 자산 | 전장 표시용 머티리얼 |
| `Assets/04_Prefabs` | Data, Initialization, Pooling, Popup, Workshop, Health, Units, Effects, UserInterface | 관리자·장면 초기화·공방·체력바·유닛·효과 프리팹 |
| `Assets/05_Scripts/Runtime/Data` | Common, Units, Stage, Navigation, Rewards | `ProjectT.Data`의 데이터 정의와 DataManager |
| `Assets/05_Scripts/Runtime` | Battle, Deployment, Economy, Initialization, Navigation, Presentation, Rewards, Timing, Units | `ProjectT.기능명`의 런타임 구현 |
| `Assets/05_Scripts/Editor/Data` | 데이터별 창·초안·생성·검사·미리보기·시험 복사본 | `ProjectT.Editor.Data` |
| `Assets/05_Scripts/Editor/Stage` | 제작·연결 도구 | `ProjectT.Editor` |

예를 들어 캐릭터 정의 코드는 `Runtime/Data/Units`, 실제 캐릭터 설정 자산은 `02_Res/Data/Character`, 적 설정 자산은 `02_Res/Data/Enemy`에 둔다. 데이터 정의와 게임 중 변경되는 상태를 구분한다. 최대 체력·가격은 정의 자산에, 현재 체력·잔액은 개별 전투 인스턴스에 둔다.

자산 이동은 Unity `AssetDatabase.MoveAsset`으로 진행하여 기존 식별자를 유지했다. 어셈블리는 `ProjectT.Runtime`, `ProjectT.Editor`, `ProjectT.Editor.Tests`, `ProjectT.PlayMode.Tests`로 단순화했다. `MovedFrom`의 이전 이름은 직렬화 이관 정보이므로 현재 네임스페이스와 다르더라도 삭제하지 않는다.

## 데이터 편집기

`Project T > 데이터`에서 클래스·적·스테이지·경로·재화·아이템의 독립 창을 연다. 창 내부의 데이터 분류 탭은 없으며 SWUtils의 공통 테마·내장 인스펙터 스타일과 유틸리티를 활용한다. 목록은 아이콘·자산명·타입, 오른쪽은 간결한 속성 입력이다. 전체 화면 규칙은 전체 기획서 12.3절을 따른다.

| 구성 | 책임 |
| --- | --- |
| `ProjectDataEditorWindow`와 종류별 창 | 목록·검색·도구 메뉴·입력 구성. 종류별 선택과 초안 분리 |
| `ProjectDataEditSession` | 원본과 초안 분리, 외부 변경 감지, 검사 후 적용·저장·실행 취소 |
| `ProjectDataCatalog`, `ProjectDataValidation` | 지원 종류·폴더·한글 설명·참조와 수치 검사 |
| `ProjectDataAssetService` | 유효한 템플릿 생성·복제, 이름 중복 회피, 원본과 공유 참조 보존 |
| `ProjectDataPreview`, `ProjectDataTrialService` | 미리보기와 기준 장면·전투 데이터의 시험용 복사본 |
| `ProjectDataEditor.uss` | SWUtils 테마를 활용한 목록·인스펙터 배치 |

자산은 종류별 기존 폴더에 저장하며 재화는 `Assets/02_Res/Data/Currency`, 아이템은 `Assets/02_Res/Data/Items`를 사용한다. 시험 복사본은 `Assets/Temp/ProjectDataTrials`에 만든다. 초안의 `SessionState` 보관은 같은 Unity 세션에 한하며 게임 영구 저장을 대신하지 않는다.

## 보상 정의·계산·지급

- `Runtime/Data/Rewards`: `RewardData`의 공통 이름·아이콘·기본 수량, `CurrencyData`·`ItemData`, 적별 참조·수량 덮어쓰기·확률을 담은 `RewardEntry`. 기본 보상 수량과 보유 잔액은 다른 개념이다.
- `Runtime/Rewards/RewardCalculator`: 전체 입력 검증 후 각 항목의 독립 확률을 판정해 `RewardAmount` 목록을 반환한다. 원본 정의나 지갑을 변경하지 않는다.
- `Runtime/Rewards/BattleRewardService`: 계산 결과 중 스테이지의 `DeploymentCurrency`와 같은 자산만 합산해 `BattleDeploymentWallet`에 지급한다. 실패 시 부분 지급하지 않는다.
- `BattleSession`: 적 처치 시 보상 서비스를 호출한다. `LastCalculatedRewards`는 마지막 계산 결과이며 아이템 보유 목록·누적 획득 장부가 아니다.

Stage01Data는 `Currency/BattleCoinData.asset`, SkeletonBasicData는 해당 자산·개별 수량 10·획득 확률 100%를 참조한다. `UnitEnemyData.Rewards` 목록으로 처치 보상을 지정한다. 아이템 보관·영구 저장·저장용 식별자·설계도·장비와 특별 전리품 확보는 후속 모듈이다.

## Main과 공통 관리자

빌드 순서는 Main → Stage01_Grassland이다. Main의 `MainSceneEntry`가 공통 관리자 초기화 후 Stage01을 비동기로 연다.

공통 관리자는 루트에 두며 SWUtils의 `SWSingleton`을 사용한다.

- `DataManager`: 공통 설정 자산의 접근점. 현재 `ColorData`와 `SpriteData`를 연결한다.
- `SWPool`: 씬 전환에도 유지되는 단일 객체 풀.
- `SWPopupManager`: 공통 팝업 관리자.
- `SceneServices`: 씬에 필요한 공통 관리자가 없다면 설정된 프리팹으로 준비한다. 따라서 Editor에서 Stage01만 열고 Play해도 정상 초기화된다. 이 객체 자체는 장면과 함께 정리한다.

`DataManager.Instance.ColorData`로 공유 색상을, `DataManager.Instance.SpriteData`로 공통 아이콘을 가져온다. `Assets/02_Res/Data/Common/SpriteData.asset`의 Speed Icon 1·2·3에는 각각 1배·2배·3배 아이콘을 연결한다. 하단 배속 버튼은 텍스트 없이 현재 배속에 맞는 아이콘을 표시한다. 다른 공통 설정이 추가되면 의미 있는 타입의 참조를 DataManager에 추가한다. 모든 스테이지·캐릭터·장비 데이터를 한 관리자에 무조건 모으지 않는다. 해당 기능이 필요한 데이터는 직접 참조한다.

같은 ScriptableObject를 여러 곳에서 참조한다고 데이터 본문이 복제되지는 않는다. DataManager의 목적은 공통 설정의 접근 규칙을 정하는 것이다. `Instantiate`로 복사하거나 모든 자산을 전역에서 계속 보유하는 경우는 별도로 판단한다. [Unity ScriptableObject 설명](https://docs.unity3d.com/6000.1/Documentation/Manual/class-ScriptableObject.html)

## 씬별 풀 목록

프로젝트에서 사용하는 SWUtils 타입명은 `SWPoolCatalog`이다. 각 씬의 `SWPoolRegistry`에 해당 Catalog를 연결한다.

| 씬 | Catalog | 현재 등록 |
| --- | --- | --- |
| Main | MainPoolData | 현재 공통 재사용 대상이 없어 빈 목록 |
| Stage01 | Stage01PoolData | OrcWarriorRedUnit 2개, OrcMageRedUnit 2개, SkeletonBasicUnit 12개, AttackTrace 4개 사전 생성 |

사전 생성 수는 최대 생성 제한이 아니다. 실제 수요에 따라 풀에서 추가 생성한다. Registry는 씬 종료 시 이름·그룹 등록을 해제하고, 같은 씬을 다시 열면 등록한다. 반환된 객체는 SWPool에서 재사용한다. 새로운 스테이지에서 사용하는 목록도 별도 Catalog로 관리하며, 동시에 로드되는 씬끼리는 같은 이름의 등록·해제 충돌을 피한다.

## 공통 전투 화면

`UIs/Canvas`는 장면에 두고 그 아래 `BattleScreen` 객체만 `Assets/04_Prefabs/UserInterface/BattleScreen.prefab`의 인스턴스로 사용한다. Canvas와 입력 시스템은 공통 화면 프리팹에 포함하지 않는다. 사용자 제작 다섯 화면은 중첩 프리팹으로 유지한다. 원본 프리팹에서 그림·배치를 편집하면 공통 화면에 반영된다. `BattleScreen`은 같은 장면의 `BattleSession` 하나를 찾아 상태를 전달하며, 재화와 전투 상태를 보관하지 않는다.

새 스테이지에서는 `BattleUserInterfaceSetup.CreateForStage()`로 공통 화면과 입력 시스템을 준비할 수 있다. 각 장면의 `BattleSession`에는 `BattleMouseCommand`, `BattlePlacementCommand`, `BattlePauseController`를 연결해야 한다. 화면을 장면 간 영구 객체로 만들지 않는다.

플레이 모드에서 `UIs/Canvas/BattleScreen` 인스펙터를 열면 SWUtils 테스트 버튼으로 전투 시작·다음 라운드, 결과 확인, 스테이지 재시작을 실행할 수 있다. `testStatus`에는 단계·처치·공방 체력·입력 안내가 표시된다. 사용자가 별도 조작 화면을 제작하면 이 테스트 기능을 대체한다.

현재 코인은 기존 전투 지갑을 읽는다. 표시 함수는 재화를 지급하거나 차감하지 않으며 미연결 재화와 잔액 없음은 `-`로 표시한다. 인벤토리 아이템·필터와 성장·장비·스킬은 후속 데이터 및 기능 연결 대상이다.

통합 유닛 데이터의 `portrait`에는 화면용 초상화를 지정한다. 비어 있으면 프리팹에 연결된 대기 그림을 사용한다.

## 공방과 체력바

`ArcaneWorkshop`은 사용자가 만든 그림·Animator·세로 `ArcaneHealthBar`를 사용한다. 그림의 바닥은 현재 전장 공방 위치에 맞추고, `WorkshopAttackPoint`를 별도로 두어 적의 공격 위치가 그림 피벗에 따라 바뀌지 않게 한다.

- 실제 피해: `Hit` Trigger. 한 번 재생한 뒤 기본 상태로 돌아온다.
- 선택지 제공: `WorkshopObjectivePresentation.SetChoicesAvailable(true)` → `Alert` Bool. 선택 완료·취소에는 false. 체력 감소나 낮은 체력으로 Alert를 켜지 않는다.
- 체력 0: 애니메이션 정지, 공방 색상 어둡게 표시, 빈 체력바 배경 유지.
- 선택지 발생 시점·후보 구성은 후속 선택지 기능에서 결정한다. 현재는 호출 계약만 준비되어 있다.

`HealthBarPresentation`이 실제 체력과 ColorData의 종류별 배경·Gradient를 연결한다. 공방은 아래에서 위로, 아군·적은 왼쪽에서 오른쪽으로 채운다. `CommonHealthBar`는 두 유닛 프리팹에 중첩하여 원본 수정이 함께 반영되게 했다. 아군 사망 시 숨겼다가 부활하면 복구하며, 풀 재사용 시 새 체력에 다시 연결한다.

## 코드 작성과 실패 처리

`05_Scripts` 전체는 SWUtils 형태의 영역 구분과 한글 XML 주석을 사용한다. 조건문·반복문·함수는 여러 줄 중괄호 블록으로 작성하고, 정렬은 해당 폴더의 `.editorconfig`와 [코드 작성 규칙](CODING_STYLE.md)을 따른다.

잘못된 입력은 `SW.Util.SWLog` 경고와 `null`·`false` 반환으로 처리한다. 생성에 실패할 수 있는 일반 객체는 `Create` 함수에서 검증하며, 호출자는 성공 여부를 확인한 뒤 상태를 반영한다. 2026-09-18 기준 Standalone 개발 타겟의 `SW_DEBUG_MODE`를 활성화했다. 코드 정리 전 원본과 검증 결과는 `Logs/Development/2026-09-18/CodeStyleRevision`에 보관한다.

## 검증과 복구 자료

2026-09-22 사용자 요청으로 `Assets/05_Scripts/Tests`, `Tools/Verification`과 일회성 표시 이전 스크립트를 제거했다. 직접 사용하는 `BattleScreen` 인스펙터 테스트 버튼과 데이터 편집기의 시험 전투는 유지한다. 자동 테스트·검증·마이그레이션 코드를 추가할 때는 먼저 사용자 확인을 받는다. 아래 과거 검증 기록은 이력이며 제거한 도구를 다시 생성하거나 실행하라는 지침이 아니다.

현재 화면 비율은 사용자 첨부 Tangy TD 이미지보다 살짝 작은 크기를 목표로 한다. 출력 및 Canvas는 1920 × 1080, Pixel Perfect Camera 내부 기준은 1536 × 864 / 단위당 32픽셀, 월드 범위는 48 × 27이다. `StageOneBattlefieldLayout`에서 기준을 정의하며, 씬 작성과 표시 개선 모두 같은 카메라 설정을 사용한다. 내부 화면의 1.25배 확대이므로 엄격한 정수 배율 Pixel Perfect는 아니다. 표시 확대 검증과 전후 화면은 개발 체크 기획서 2.12절 및 `Logs/Development/2026-09-18/DisplayScaleRevision/`에 기록한다.

공통 전투 화면 검증은 개발 체크 2.13절, 데이터 편집·보상 기반의 최신 범위와 검증은 2.14절을 따른다. 개편 전 자산은 `Logs/Development/2026-09-18/StructureRevision/BeforeRevision.zip`에 보관했다. 이전 에이전트의 임시 스테이지 사본은 같은 로그 폴더로 옮겼다. 활성 프로젝트에서 구형 MobileArcaneWorkshop, 선으로 만든 공방 체력바 스크립트, 빈 Defense 폴더를 제거했다.

## 종류별 유닛과 애니메이션

`UnitData`를 공통 부모로 두고 `UnitClassData`, `UnitEnemyData`에 능력치·표시 정보·종류별 프리팹을 통합한다. 기존 Appearance 자산과 별도의 동작별 프레임 배열은 사용하지 않는다. ScriptableObject 스크립트와 자산 이름은 `Data`로 끝난다.

- 캐릭터: `OrcWarriorRedData`, `OrcMageRedData`. 기존 전사·마법사의 능력치를 유지한다.
- 적: `SkeletonBasicData`, `SkeletonRedData`, `SpiderGreenData`, `SpiderPurpleData`. 기본 해골의 능력치·보상을 유지하고 나머지 3종은 사용자가 Unity에서 직접 입력한다. 미설정 적은 생성 검증에서 거절하며 Stage01에는 등록하지 않는다.
- 프리팹: `Units/Character/CharacterUnitBase`, `Units/Enemy/EnemyUnitBase`를 상속한 `<종류>Unit` 변형을 사용한다. 데이터의 `Prefab` 참조로 생성할 종류를 결정한다.
- Animator와 `UnitAnimation`은 SpriteRenderer와 같은 `CharacterVisual` 객체에 연결한다. `Walk`·`Death` 파라미터와 대기·공격·사망 상태 재생을 코드에서 제어한다.
- 공격 클립에는 사용자가 지정한 시점의 `AttackImpact` 이벤트를 연결한다. 이벤트 없이 시간이 흐르는 것만으로는 피해를 적용하지 않는다. 중복 이벤트·취소·사망·이전 대상의 생명에는 피해를 중복 적용하지 않는다.
- 공격 간격이 원본 클립보다 짧으면 해당 공격을 간격 안에 재생하도록 속도를 올린다. 간격이 길면 원래 속도로 끝내고 다음 공격을 기다린다. 이동·사망은 기본 속도를 사용한다.
- 적 처치 정산과 전투 목록 제거는 즉시 수행하며, 사망 클립을 마친 다음 SWPool로 반환한다.

새 종류를 추가할 때는 기본 프리팹의 변형, Animator/클립, 데이터의 Prefab과 능력치를 연결한다. 클립 이름·상태·이벤트를 바꾸면 변형 프리팹의 UnitAnimation 설정도 함께 확인한다.
