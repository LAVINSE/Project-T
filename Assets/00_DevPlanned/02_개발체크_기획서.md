# Project T 개발 체크

수정일: 2026-09-24 · 버전: 0.23

[게임 규칙](01_전체세부_기획서.md) · [변경 기록](<03_신규콘텐츠 및 주요변경_기획서.md>) · [구조 가이드](04_프로젝트구조_가이드.md)

이 문서는 현재 구현 범위, 남은 개발, 사용자 확인 항목을 관리한다. **구현 완료와 실제 사용 확인을 구분한다.** 이번 갱신은 기존 작업 결과를 반영한 문서 수정이며 새 기능 개발이나 게임 실행 검증은 포함하지 않는다.

## 작업 진행 규칙

1. 작업의 목적·범위·동작·화면·저장·확인 방법을 설명하고 사용자 확인을 받는다. 이미 승인한 규칙은 다시 미정으로 돌리지 않는다.
2. 확장·수정 중 새 결정이 필요하면 차이가 드러나는 선택지를 제시한다. 질문을 보낸 뒤에는 구현·문서 수정·읽기 전용 조사·다른 작업을 모두 멈추고 답변을 기다린다.
3. 답변으로 승인한 작업만 진행한다. 로드맵 등록을 다음 작업의 자동 승인으로 해석하지 않는다.
4. Unity 개발과 연결에는 Unity CLI를 사용한다. 코드 규칙은 [CODING_STYLE](CODING_STYLE.md)을 따른다.
5. 기획서는 개발 중간에 갱신하지 않는다. 사용자가 최종 갱신을 요청하면 결과를 한 번에 반영한다.
6. 실제 사용 검증은 사용자가 별도로 진행한다. 개발 결과에는 컴파일 확인과 미확인 동작을 구분해 남긴다.
7. 자동 테스트·일회성 검증·마이그레이션 코드, 백업·스냅샷은 승인 없이 추가하지 않는다. 삭제한 Tests·시험 장면 자동 복제 기능을 다시 만들지 않는다.

기존 단계 0~7을 유지한다. 선행 기반이 구현된 항목은 다시 만들지 않으며 각 작업의 상세 내용은 착수 전에 확인한다.

| 단계 | 현재 상태 | 남은 개발 | 함께 만들 화면·편집 |
| --- | --- | --- | --- |
| 0. 전투 기반 | 구현 | 사용자 피드백에 따른 수정 | 기본 전투 조작·안내 |

다음 개발 후보는 **장비 장착과 효과 적용**이다. 장비 데이터가 준비됐다는 이유만으로 장착 방식·중복 제한·체력 변화 규칙까지 확정하지 않는다.

시작 화면, 진행 중 전투 이어하기, 출전 편성 방식, 설정 항목·소리·추가 조작 장치는 별도 결정 대기다. 출시 플랫폼 상세·가격·스팀 연동·배포 준비도 현재 단계에 포함하지 않는다.

## 이번에 반영한 개발 결과

### 보상·장비

- 특별 전리품을 직접 확보하는 기획을 자동 입고로 교체했다. 저장 성공 알림에 인벤토리 아이콘 연출을 연결했다.
- 장비 아이콘, 희귀도, 성능 등급, 공용 스탯 효과와 등급별 포함·증가량 설정을 구현했다.
- EquipmentFixedStatEffectData를 EquipmentStatEffectData로 변경했다. 스크립트 GUID를 유지했다. 사용자가 만든 자산 파일 이름까지 일괄 변경한 것은 아니다.
- 선택된 등급은 체크된 모든 스탯을 포함한다. 증가량 재정의는 기본값을 교체한다.
- 성능 등급을 가중치로 추첨하고 개수마다 등급별 ItemData로 변환한다. 추첨 가능한 등급별 등록 아이템의 누락·중복을 지급 전에 검사한다.
- 보상 재시도 시 등급을 다시 뽑지 않는다. 요청당 장비 추첨 10,000회 제한은 과도한 작업 방지용이며 보유 한도가 아니다.
- 실제 장착·캐릭터 효과 적용·제작은 구현하지 않았다.

### 능력치

- 기본 5개·추가 7개·캐릭터 운영 3개·적 공방 공격 2개·공방 최대 체력 1개를 SWStat으로 통일했다.
- SWStatOverride 설정과 RuntimeStatCollection의 소유자별 복제본을 사용한다. 원본 스탯 자산을 전투 중 변경하지 않는다.
- 공격·이동·사거리·최대 체력 표시 등에 실행값을 연결했다. 증가량은 출처별 적용·제거가 가능하다.
- 전환 작업에서 7개 자산의 기존 수치 59개를 보존한 것으로 확인했다. 미설정 적 3종의 0값도 유지했다.
- 추가 능력치 7개의 실제 전투 공식과 경험치·레벨 진행은 남겨 두었다.

### 편집기

- 아이템·장비·장비 효과·장비 등급·스탯을 한 창의 탭으로 묶었다. 클래스·적·스테이지·경로·재화는 별도 창을 유지한다.
- 관련 폴더의 분류만 선택하게 하고 Ping·에셋 파일명·표시 이름·코드명 편집을 보강했다.
- 중첩 생성·관리 버튼과 입력 옆 ‘…’ 메뉴를 제거했다.
- 모든 Project T 데이터 편집기의 저장과 검사를 분리했다. 빈 값·오류가 있는 초안도 저장·생성·복제할 수 있다.
- 네이티브 객체 선택기의 선택값이 사라지지 않도록 등급 효과 참조 반영과 스탯 영역 갱신을 분리했다.
- 스탯마다 여러 줄로 나뉘던 입력을 ‘사용 | 스탯 | 기본값 | 값 변경 | 최종’ 표로 정리했다.

### 전투·스탯

- [ ] SWStat 전환 후 기존 전사·마법사·기본 해골의 공격·이동·부활·비용이 유지된다.

- [ ] 최대 체력 감소 시 현재 체력이 제한되고 증가만으로 자동 회복하지 않는다.
- [ ] 잘못된 더미 데이터를 저장할 수 있더라도 실제 배치·생성·지급에서는 거부한다.

## 확인 근거와 한계

### 콘텐츠 설정 확인

문서 대조 중 Stage01Data.asset의 enemiesPerRound 원문이 `06000000090000000c000000i`로 끝나는 것을 확인했다. 정수 배열의 16진수 표현에 맞지 않는 `i`가 있으므로 Unity에서 라운드 목록이 기획값 6·9·12명으로 읽히는지 확인이 필요하다. 이번 문서 작업에서는 자산을 수정하거나 실행하지 않았다.

### 확인 기록

| 구분 | 기록 |
| --- | --- |
| 이전 사용자 확인 | 2026-09-22 데이터 편집 결과가 스테이지에 반영된다는 확인에 따라 확인-002 완료 처리 |
| 기존 화면 확인 | 전투 진행·결과 통계와 빈 인벤토리 36칸·필터·열기/닫기·정지·파괴 팝업 기본 배치 확인 기록 있음 |
| 최근 코드 확인 | SWStat·장비·보상·편집기 수정 후 Unity 컴파일 오류 0개 확인 기록 있음 |
| 최신 편집기 수정 | 컴파일 완료. 실제 객체 선택기 더블클릭과 표 가독성은 사용 확인 대기 |
| 이번 문서 작업 | 현재 소스·자산·기존 기록을 대조해 문서 갱신. 게임 실행·빌드·새 자동 테스트는 수행하지 않음 |

과거 자동 테스트 통과 기록은 당시 버전의 증거다. 제거된 테스트 도구를 복구하거나 현재 변경까지 검증된 것으로 해석하지 않는다. TestManager의 기존 전투 시작·결과·재시작 버튼은 유지한다.

성능 목표와 최대 개체 수는 미정이다. 콘텐츠 확장 단계에서 실제 장비·해상도·개체 수를 정하고 프레임 시간, 장기 메모리 증가, 풀 반환, 이동·효과 표시 비용을 확인한다.
