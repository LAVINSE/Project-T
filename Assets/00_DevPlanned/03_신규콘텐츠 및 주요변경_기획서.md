# Project T 신규 콘텐츠·변경 기록

수정일: 2026-09-26 · 버전: 0.32

[게임 규칙](01_전체세부_기획서.md) · [개발 체크](02_개발체크_기획서.md)

이 문서는 결정이 바뀐 이유와 미채택 후보를 남긴다. 현재 규칙은 전체 기획서, 구현·사용 확인 상태는 개발 체크를 기준으로 한다. 각 변경에는 이유·결정·대체한 규칙만 적고 규칙 전문은 반복하지 않는다. 과거 변경의 제목은 당시 내용을 식별하기 위한 기록이며 폐기된 규칙을 다시 적용하지 않는다.

## 최근 변경

### 변경-031: 특별 전리품 자동 획득

사용자 결정: 특별 전리품을 직접 확보할 필요 없이 인벤토리에 자동으로 넣고, 획득 시 인벤토리 아이콘을 연출한다. 스테이지 클리어 추가 보상은 제외한다.

| 이전 | 현재 |
| --- | --- |
| 특별 전리품을 바닥에 남기고 캐릭터 이동·확보·취소·회수 | 일반 아이템과 같은 자동 입고·저장 경로 사용 |
| 미확보 전리품을 라운드·최종 휴식에서 회수 | 회수 조작 없음. 휴식의 이동·재배치·부활 규칙은 유지 |
| 확보 완료 시 영구 보존 | 저장·지급 성공 시 영구 보존 |
| 드롭 위치·확보 진행 표시 | 특별 전리품 저장 후 인벤토리 아이콘 확대·복귀 |

특별 전리품 여부는 아이템 분류와 별개인 ItemData 설정이다. 규칙은 [전체 기획서의 특별 전리품](01_전체세부_기획서.md#특별-전리품)을 따른다.

### 변경-032: 장비 등급·공유 효과·가중치 드롭

사용자 결정: 일반 장비에도 성능 차이를 두어 파밍하도록 한다. 희귀도와 성능 등급은 선택 목록으로 연결하고, 같은 스탯 효과를 공유하면서 등급별 수치를 덮어쓴다. 등급별 체크로 특정 스탯을 포함하거나 제외한다.

- 별도의 ‘스탯 등급’과 등급 결정 후 스탯 재추첨은 두지 않는다. 등급이 정해지면 체크된 스탯을 모두 포함한다.
- 등급마다 효과 자산을 만들지 않고 공유 효과 하나를 여러 등급이 참조한다.
- 인벤토리는 기존 구조를 유지해 등급별 ItemData로 저장한다.
- 손에 드는 장비 외형은 만들지 않는다.

규칙은 [전체 기획서의 장비](01_전체세부_기획서.md#장비)를 따른다.

### 변경-033: 능력치를 SWStat으로 통일

사용자 결정: 스탯은 SWStat으로 관리하고 재화·아이템·진행 상태는 기존 역할에 맞는 데이터로 관리한다.

18개 정의를 SWStat으로 옮기고 SWStatOverride로 개별 설정을, RuntimeStatCollection으로 소유자별 실행값을 관리한다. SWStat 연결을 추가 능력치 전투 효과의 구현 완료로 보지 않는다. 전투 공식은 변경-042에서 구현했다. 규칙은 [전체 기획서의 능력치](01_전체세부_기획서.md#능력치)를 따른다.

### 변경-034: 편집기 통합과 선택적 검사

사용자 결정: 관리 창을 계속 늘리지 않고 통합 가능한 항목을 묶는다. 저장 때마다 유효성 검사로 막지 말고, 더미·빈 데이터도 저장하며 원할 때만 검사한다.

| 이전 | 현재 |
| --- | --- |
| 데이터 종류마다 별도 편집 창 | 아이템·장비·장비 효과·장비 등급·스탯을 한 창의 탭으로 통합 |
| 검사를 통과해야 적용·저장 | 저장과 ‘검사하기’ 분리. 빈 값·미완성 데이터도 저장·생성·복제 |
| 장비 설정 안에서 분류 생성·관리 | 분류는 해당 탭에서 만들고 장비에서는 연결만 |

규칙은 [전체 기획서의 데이터 편집](01_전체세부_기획서.md#데이터-편집)을 따른다.

### 변경-035: 장비 효과 이름·참조 선택·스탯 표

사용자 지적: 장비 효과의 이름이 현재 역할과 맞지 않고, 원형 선택 버튼에서 자산을 더블클릭해도 등급 효과가 들어가지 않는다. 참조 메뉴와 여러 줄 스탯 입력도 혼동을 준다.

| 문제 | 조치 |
| --- | --- |
| 이름이 역할과 맞지 않음 | EquipmentFixedStatEffectData → EquipmentStatEffectData. 스크립트 GUID 보존, 사용자 자산 파일 이름은 그대로 |
| 더블클릭한 참조가 사라짐 | 참조를 초안에 먼저 반영하고 스탯 영역만 다시 그림. 객체 선택 중 입력 필드가 교체되는 경로 분리 |
| 여러 줄 스탯 입력이 혼동됨 | ‘사용 \| 스탯 \| 기본값 \| 값 변경 \| 최종’ 한 줄 표. 체크 해제는 ‘제외’, 재정의 해제는 공유값 표시 |
| ‘…’ 참조 메뉴가 혼동됨 | 입력 옆 참조 열기·복제 메뉴 제거. 별도 참조·사용처 화면은 유지 |

편집기 참조 선택 문제에 대한 수정이며 장착 기능을 구현한 것은 아니다.

### 변경-036: 기획서 일괄 갱신과 문장 정리

변경-031~035를 반영했다. 폐기된 직접 확보·클리어 추가 보상·검사 필수 저장 규칙을 현행 규칙에서 제거하고, 기존 후보를 미채택 후보로 모았다.

### 변경-037: 중복 제거와 개발 지침 정리

사용자 요청: 기획서의 중복을 없애고 My Unity Skills 지침에 맞게 정리한다. 수치 대조는 하지 않는다.

| 이전 | 현재 |
| --- | --- |
| 같은 편집기·스탯·장비 설명을 세 문서에 반복 | 규칙은 전체 기획서, 구현 상태는 개발 체크, 사유는 변경 기록에만 두고 나머지는 링크 |
| 전체 기획서에 구현 상태와 ‘제거했다’ 같은 이력 혼재 | 전체 기획서는 규칙과 미정 항목만 기록 |
| 남은 결정이 전체 기획서와 개발 체크에 중복 | 개발 체크의 결정 항목 표로 일원화 |
| 개발 체크에 스킬 지침과 같은 작업 규칙 7개 | 지침 참조와 프로젝트 전용 규칙 4개 |
| 삭제된 구조 가이드·CODING_STYLE 링크 | 링크 제거. 코드 규칙은 My Unity Skills 지침 |
| Stage01 라운드 배열 확인 필요 | Unity CLI로 6·9·12 확인 후 미확인 항목 제거 |

코드·장면·자산은 수정하지 않았다.

### 변경-038: 사용자 인벤토리 정보·호버·버리기 UI 연결

사용자 요청: 직접 제작한 InventorySlotInfo UI와 Hover Box Slice를 연결하고, ColorData·SpriteData의 등급 색상/박스를 사용한다. DiscardSlot에 놓을 때도 버리기 확인을 열며 정보 팝업 크기는 스탯 개수에 맞춘다.

기존 정보·버리기 화면을 사용자 프리팹으로 교체했다. 기존 소유·저장·수량 선택 경로를 사용하고 등급 외형은 기존 희귀도 분류에 연결했다. 색상·스프라이트 설정은 원래 값을 유지하며 분류별 목록으로 관리한다. 당시 미구현 판매가 영역은 숨겼으며 후속 변경-039·040에서 가격과 재화 표시를 연결했다. 규칙은 [인벤토리 조작](01_전체세부_기획서.md#인벤토리-조작), 결과와 미확인 동작은 [개발 체크](02_개발체크_기획서.md#최근-개발-결과)를 따른다.

### 변경-039: 판매가 데이터와 인벤토리 수동 테스트

사용자 요청: 아이템·장비에 판매가 데이터를 추가하고, 인벤토리 기능 확인용 Test 기능과 더미 아이템·장비를 제공한다.

일반 아이템은 ItemData, 장비는 EquipmentData에 1개당 판매가를 둔다. 연결한 장비 아이템은 장비 가격을 사용하며 정보 팝업의 기존 판매가 영역을 다시 연결했다. 기존 TestManager에 지급·동일 요청 재시도·테스트 목록 제거·인벤토리 열기 버튼을 추가했다. 더미 가격과 스탯은 기능 확인용이고 정상 적 드롭에는 연결하지 않았다. 규칙은 [인벤토리 조작](01_전체세부_기획서.md#인벤토리-조작), 사용법과 결과는 [개발 체크](02_개발체크_기획서.md#인벤토리-수동-테스트-사용)를 따른다.

### 변경-040: 판매 재화와 인벤토리 자유 배치

사용자 요청: 판매가의 재화를 코인으로 단정하지 않고 CurrencyData로 선택하며, 아이템을 집으면 원래 슬롯에서 떼어 마우스 위치에 맞게 표시한다. 빈 슬롯 이동·점유 슬롯 교환을 지원하고 잘못 놓으면 원래 위치로 복귀한다. 창 밖과 DiscardSlot에서는 버리기 확인을 받는다.

판매 재화·아이콘/이름 표시를 연결하고 장비 아이템은 장비 정의의 판매 정보를 함께 사용하도록 변경했다. 기존 선택 박스 효과를 제거하고 CarriedItemGroup으로 아이콘·수량을 포인터 중심에 표시한다. 자유 배치와 빈칸 저장을 추가하면서 기존 저장의 수량·지급 기록과 호환을 유지했다. 변경-030의 빈 슬롯 놓기 취소 규칙을 이동/교환으로 대체한다.

인벤토리 초기화 중 CancelCarry의 NullReferenceException은 현재 프리팹에 없는 instructionText 참조를 제거해 수정했다. 이 수정과 마우스 위치 변경은 컴파일·참조 확인까지 진행했으며 실제 Play 재확인은 남아 있다. 규칙은 [인벤토리 조작](01_전체세부_기획서.md#인벤토리-조작), 호환 범위는 [저장](01_전체세부_기획서.md#저장), 검증 상태는 [개발 체크](02_개발체크_기획서.md#확인-기록)를 따른다.

### 변경-041: 전투 중 장비 장착과 정지 중 조작

사용자 요청: 인벤토리를 열어도 전투를 멈추지 않고 필드 캐릭터를 선택해 CharacterHUD 장비 슬롯으로 장착·교체한다. Pause 중에도 캐릭터 선택·이동 명령 예약·장비 변경을 허용하고 정지를 풀면 예약한 곳으로 이동한다. 추가 답변으로 같은 캐릭터의 동일 장비 중복 장착을 금지하며 스킬 구현은 추후 진행하기로 했다.

기존 HUD 두 슬롯에 장착·교체·우클릭 해제를 연결하고 수량 점유, 성능 등급과 무관한 동일 장비 판정, 개체별 스탯 합산/제거와 종료 반환을 구현했다. 인벤토리의 자동 정지와 전체 외부 영역 입력 차단을 제거하고 아이템 집기·버리기 확인 중에만 필드 입력을 제한한다. Pause의 시뮬레이션 정지와 선택/예약 입력을 분리하고 캐릭터별 최신 유효 목적지를 재개 시 실행한다.

변경-010·016의 인벤토리/장비 화면 정지 규칙과 장착 미구현 상태를 대체한다. Pause 중 스킬 교체 허용은 향후 규칙이며 스킬 UI·교체·발동을 구현한 것은 아니다. 규칙은 [진행과 시간](01_전체세부_기획서.md#진행과-시간) 및 [장착과 제작](01_전체세부_기획서.md#장착과-제작), 남은 검증과 로드맵은 [개발 체크](02_개발체크_기획서.md)를 따른다.

### 변경-042: 전투 보조 능력치 공식

사용자 결정: 방어·치명타·회피·흡수·관통을 실제 전투에 적용한다. 방어는 비율 감소, 치명타·회피는 확률값과 기본 1.5배 배율로 하고, 적에게는 방어·회피만 준다.

| 이전 | 현재 |
| --- | --- |
| 추가 능력치 7개는 표시만 하고 전투 계산에 쓰지 않음 | 회피 → 치명타 → 방어·관통 → 피해 → 생명력 흡수 순서로 기본 공격에 적용 |
| 캐릭터의 `additionalStats` 표시 목록 | 전투가 직접 읽으므로 이름 있는 항목으로 전환하고 목록 삭제. 방어·회피는 유닛 공통, 나머지는 캐릭터 전용 |
| 적은 보조 능력치 없음 | 적도 방어·회피를 가짐. 기존 값은 모두 0 |
| 확률형 능력치를 소수로 표시 | 치명타 확률·치명타 피해·회피·생명력 흡수를 백분율로 표시 |

- 고정 차감·퍼센트 방어율 방식과 치명타 피해를 전체 배율로 쓰는 방식은 채택하지 않았다.
- 모든 값이 0이면 기존 전투와 결과가 같다. 스킬 가속 공식은 스킬 단계에서 정한다.
- 치명타·회피 화면 연출은 이번 범위에 포함하지 않았다.

규칙은 [전체 기획서의 피해 계산](01_전체세부_기획서.md#피해-계산)을 따른다.

### 변경-043: 우클릭 취소 수정과 전투 공식 수동 테스트

사용자 요청: Play 대신 정적 검증을 먼저 진행한다. 발견한 문제를 함께 고치고, 전투 공식을 확인하기 쉽게 한다.

| 문제 | 조치 |
| --- | --- |
| HUD 장비 슬롯 위에서 집기를 우클릭으로 취소하면 장비도 해제됨 | 취소는 누를 때, 해제는 뗄 때 처리되던 차이를 막기 위해 취소에 쓴 우클릭을 뗀 프레임까지 소비된 입력으로 처리 |
| 확률 판정과 체력바만으로는 공식 확인이 어려움 | TestManager에 임시 능력치 적용·제거 버튼과 타격 계산 로그를 추가. 피해 숫자 연출은 채택하지 않음 |

정적 검증에서 전량이 장착된 장비의 칸에 다른 아이템을 놓으면 해제 후 복귀 칸이 바뀌는 경미한 문제를 발견했다. 수량 손실이 없어 수정하지 않았다. 사용법과 기준값은 [개발 체크](02_개발체크_기획서.md#전투-공식-수동-테스트-사용)를 따른다.

### 변경-044: 설계도와 제작

사용자 결정: 설계도는 영구 해금, 결과 등급은 드롭과 같은 가중치 추첨, 비용은 재료와 소울이다. 제작 화면은 거점 구현 후 만든다. 설계도는 인벤토리 우클릭으로 즉시 사용하고 버릴 수 없으며, 배웠거나 보유 중이면 다시 드롭하지 않는다. 비용은 상속 모듈 없이 ScriptableObject 수치로 두고 공통 기본값을 제작법별로 덮어쓰며 0이면 필요 없다.

| 이전 | 현재 |
| --- | --- |
| 설계도 분류만 있고 사용 기능 없음 | 제작법을 연결한 아이템이 설계도. 우클릭으로 1개 소모해 해금 |
| 소울 소비 기능 없음 | 제작 비용으로 차감. 인벤토리 저장 실패 시 반환 |
| 인벤토리 저장 형식 1 | 형식 2에 해금 목록 추가. 형식 1도 읽음 |

- 획득 즉시 자동 해금, 첫 1개만 소모, 제작 시 설계도 소모, 설계도 없는 제작은 채택하지 않았다.
- 레시피별 고정 등급과 최소 등급 보장은 채택하지 않았다.
- 성공 안내("배웠습니다")와 "이미 배운 설계도" 안내는 사용자 요청으로 제거했다. 중복 획득이 없으므로 후자는 발생하지 않는다.
- 재료 검사는 기존 RewardEntry와 같은 항목별 Validate로 두고, 중복 재료 검사는 각 소유 데이터가 한다.

규칙은 [전체 기획서의 설계도와 제작](01_전체세부_기획서.md#설계도와-제작), 확인 방법은 [개발 체크](02_개발체크_기획서.md#제작-수동-테스트-사용)를 따른다.

### 변경-045: 거점 최소 루프

사용자 결정: 거점을 먼저 만들어 결과 → 거점 → 재출전을 연결한다. 거점에는 출전(스테이지 선택)·제작·인벤토리·소울 잔액을 두고, 제작은 거점에서만 한다. UI는 기존 스프라이트로 기본 배치를 만들고 사용자가 이후 꾸민다. 성장(연구)은 이번 범위에서 제외했다.

| 이전 | 현재 |
| --- | --- |
| 결과 화면의 거점 버튼 비활성 | 결과 확정 후 거점으로 이동 |
| 게임 시작 시 스테이지 1로 바로 진입 | 거점에서 출전 |
| 제작은 TestManager로만 확인 | 거점 제작 창에서 배운 설계도 선택·비용 확인·제작 |
| 스테이지와 장면의 연결 없음 | StageData에 빌드 설정에 등록된 장면 경로 |

- 제작을 전투 휴식에서도 허용하는 안은 채택하지 않았다.
- 인벤토리는 전투와 같은 프리팹을 재사용하며 거점에서는 장비 장착을 하지 않는다.

규칙은 [전체 기획서의 게임 흐름](01_전체세부_기획서.md#게임-흐름)을 따른다.

### 변경-046: 타이틀과 Bootstrap

사용자 결정: 저장 슬롯은 하나만 쓰므로 타이틀에는 이어하기·새 게임·슬롯 선택 없이 「게임 시작」과 「게임 종료」만 둔다. 거점에서 타이틀로 돌아가는 버튼은 두지 않는다. 관리자 준비 장면과 타이틀을 분리하고, 화면 없이 관리자만 준비하는 Main 장면의 이름을 Bootstrap으로 바꾼다.

| 이전 | 현재 |
| --- | --- |

### 변경-047: 공통 연구 트리

사용자 결정: 공통 성장을 **트리**로 만든다. 모든 노드는 1회, 노드마다 고정값 또는 비율 효과를 고르며, 선으로 이어진 앞 노드 중 하나를 완료하면 열린다. 트리는 그래프 드래그 편집기로 만든다. 사용자가 SWUtils의 SWSkillTree를 사용하도록 안내했다. 비율은 클래스 기본값 기준, 비용은 소울 고정, 개별 환불과 전체 초기화를 모두 두고 화면은 SWSkillTreeView를 한글화해 쓴다.

| 이전 | 현재 |
| --- | --- |
| 공통 성장은 방향만 확정 | 거점 연구 창에서 소울로 연구, 배치되는 모든 아군에 적용 |
| 소울 사용처는 제작뿐 | 연구 비용·환불·초기화 추가 |
| 트리 편집·화면 기능 없음 | SWSkillTree 편집기·실행·화면을 사용하고 효과·지갑·저장·한글 표시만 프로젝트에 맞게 추가 |

- 단계형 목록(레벨업)과 목록+선행 조건 방식은 채택하지 않았다.
- 노드별 여러 레벨, 앞 노드 모두 필요, 앞 노드 특정 레벨 조건은 채택하지 않았다.
- 비율을 장비 포함 최종값에 곱하는 방식과 재료 비용은 채택하지 않았다.
- 표 편집 + 미리보기 방식 대신 SWSkillTree의 그래프 편집기를 쓴다.
- SWSkillTree는 구매 중 되돌리기를 허용하지 않으므로, 소울 저장 후 연구 저장이 실패하면 다음 변경 때 다시 저장한다.

규칙은 [전체 기획서의 공통 연구](01_전체세부_기획서.md#공통-연구)를 따른다.

## 미채택 후보

아래 내용은 아이디어 보존용이다. 기본 게임 규칙이나 현재 개발 승인 범위가 아니다.

### 전장 재건

한 맵의 복구 부지에서 다리와 보급소를 비교한다. 다리는 아군 이동 시간을 줄이고 보급소는 범위 지원을 제공하는 안이다. 첫 승리 뒤 해금, 첫 선택·전투 밖 변경은 무료인 시험안을 검토했다. 지원 효과·영구 비용 여부는 미정이다.

시설은 다음 출전부터 적용하고 맵·부지·선택을 저장하는 안이다. 최소 비교 범위는 맵 1개·시설 2개·편성 2개다. 한 시설만 정답이 되거나 제작 부담이 크면 시각적 복구만 남기거나 보류한다.

### 계승 원정

장기 성장 정체가 확인된 뒤 환생형 반복을 원하는지 결정한다. 지역 묶음 돌파 후 사용자가 원정을 재편하고 대표 전술 하나를 계승하는 안이다.

| 유지 후보 | 초기화 후보 |
| --- | --- |
| 지역 접근·클래스/특성 해금·클래스 훈련·훈련 재료·계승 점수·재건·사용자 설정 | 공통 전력 연구·연구 재료·현재 원정 위협 진행·진행 중 전투 |

한 맵 선택은 원정과 무관하게 새 출전에서 초기화한다. 계승 보상 계산식은 미정이며 같은 달성 기록을 반복 지급에 쓰지 않는다. 이 후보를 채택해도 클리어 추가 보상이 자동으로 되살아나는 것은 아니다.

재편 전후에 잃는 값·남는 값·보상을 보여주고, 보상과 초기화를 한 저장 단위로 처리해야 한다. 대안은 초기화 없이 상위 위협·연구 상한을 확장하거나 별도 도전 모드를 만드는 것이다.

### 협동 전술

둔화된 적에 특정 공격이 명중하면 추가 관통하는 식의 조합 후보다. 같은 공격에서 재귀 발동하지 않도록 하며 해금·발동 조건·효과 수치는 미정이다. 사거리 겹침과 편성이 실제 선택을 만드는지 확인한 뒤 채택한다.

### 전술 계약

승리한 맵에서 추가 제약과 보상을 출전 전에 선택하는 안이다. 빠른 적 추가 등을 비교하되, 없는 기능을 제한 조건으로 만들지 않는다. 계약 없는 출전도 허용하는 후보이며 위협 강화와의 중복·실패 보상·수익을 먼저 검토한다.

### 신병 전수

새 클래스가 성장 격차 때문에 쓰이지 않을 때 첫 특성을 무료 또는 낮은 비용으로 제공하는 안이다. 공통 성장만으로 해결되는지 먼저 보고, 기존 클래스 소급 지급·투자 가치·중복 지급 규칙을 정한다.

### 파밍·콘텐츠 후보

- 맵별 주요 재료를 달리해 목표 보상에 따라 출전지를 고른다.
- 안전한 강화와 추가 정예의 보상 기회를 비교한다.
- 클래스 성장으로 전투 선택 후보를 해금한다. 후보 증가가 원하는 빌드를 오히려 어렵게 만들지 확인한다.
- 옆길의 별도 수색 지점에 전력을 보내는 안은 미채택이다. 폐기한 특별 전리품 직접 확보와 함께 자동 채택하지 않는다.
- 외형·공격 연출 해금, 별도 영웅·지원 주문, 개체 구매 강화·판매/철수는 채택 여부부터 결정한다.

과거 연구 배율·비용표와 체험판·출시의 맵/클래스 수는 비교용 초안이다. 현행 경제나 제작 수량으로 사용하지 않는다.
