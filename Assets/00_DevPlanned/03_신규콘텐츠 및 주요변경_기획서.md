# Project T 신규 콘텐츠·변경 기록

수정일: 2026-09-24 · 버전: 0.23

[게임 규칙](01_전체세부_기획서.md) · [개발 체크](02_개발체크_기획서.md) · [구조 가이드](04_프로젝트구조_가이드.md)

이 문서는 결정이 바뀐 이유와 미채택 후보를 남긴다. 현재 규칙은 전체 기획서, 구현·사용 확인 상태는 개발 체크를 기준으로 한다. 아래 과거 변경의 제목은 당시 내용을 식별하기 위한 기록이며 폐기된 규칙을 다시 적용하지 않는다.

## 이번 변경

### 변경-031: 특별 전리품 자동 획득

사용자 결정: 특별 전리품을 직접 확보할 필요 없이 인벤토리에 자동으로 넣고, 획득 시 인벤토리 아이콘을 연출한다. 스테이지 클리어 추가 보상은 제외한다.

| 이전 | 현재 |
| --- | --- |
| 특별 전리품을 바닥에 남기고 캐릭터 이동·확보·취소·회수 | 일반 아이템과 같은 자동 입고·저장 경로 사용 |
| 미확보 전리품을 라운드·최종 휴식에서 회수 | 회수 조작 없음. 휴식의 이동·재배치·부활 규칙은 유지 |
| 확보 완료 시 영구 보존 | 저장·지급 성공 시 영구 보존 |
| 드롭 위치·확보 진행 표시 | 특별 전리품 저장 후 인벤토리 아이콘 확대·복귀 |

ItemData의 특별 전리품 설정과 InventoryStore의 획득 알림, DOTween 연출을 구현했다. 특별 전리품 여부는 아이템 분류와 별개이며 복원·파괴·중복 지급에는 연출하지 않는다. 실제 획득 연출은 사용자 확인 대기다.

### 변경-032: 장비 등급·공유 효과·가중치 드롭

사용자 결정: 일반 장비에도 성능 차이를 두어 파밍하도록 한다. 희귀도와 성능 등급은 선택 목록으로 연결하고, 같은 스탯 효과를 공유하면서 등급별 수치를 덮어쓴다. 등급별 체크로 특정 스탯을 포함하거나 제외한다.

- 장비 정의에 인벤토리 아이콘·희귀도·성능 등급 목록을 추가했다. 손에 드는 장비 외형은 만들지 않는다. 아이콘 미등록 장비는 빈 아이콘이다.
- 희귀도와 성능 등급의 SWCategory는 Equipment/Categories에서 함께 관리한다. 별도의 스탯 등급은 두지 않는다.
- 공유 스탯 효과에서 등급별 사용 여부와 증가량 재정의를 설정한다. 체크된 스탯은 모두 포함하고 별도 스탯 추첨은 하지 않는다.
- 등급은 가중치로 선택한다. 0 가중치는 제외하며 장비 한 개마다 따로 추첨한다.
- 인벤토리는 기존 구조대로 등급별 ItemData를 저장한다. 추첨 가능한 등급마다 등록 아이템 하나가 필요하고, 효과 자산은 여러 등급에서 공유할 수 있다.
- 저장 재시도에는 계산한 등급을 재사용한다. 고정 등급을 지급하는 보상 설정도 제공한다.
- 추가 효과 참조는 향후 장비 능력을 위한 확장 지점으로 둔다.

상태: 정의·편집·등급별 효과 계산·표시·드롭 연결 구현. 장착 2슬롯·캐릭터 효과 적용·제작·장비 능력 발동은 미구현이다.

### 변경-033: 능력치를 SWStat으로 통일

사용자 결정: 스탯은 SWStat으로 관리하고 재화·아이템·진행 상태는 기존 역할에 맞는 데이터로 관리한다.

기본 능력치 5개, 추가 능력치 7개, 저지 수·부활 대기시간·배치 비용, 적의 공방 공격 피해·간격, 공방 최대 체력의 18개 정의를 연결했다. SWStatOverride로 개별 설정을 보존하고 RuntimeStatCollection으로 소유자별 실행값을 관리한다.

현재 체력·잔액·보유 수량·레벨·경험치·남은 시간은 별도 상태다. 추가 능력치 7개의 전투 공식은 후속이며, SWStat 연결을 해당 전투 효과의 구현 완료로 보지 않는다. 기존 수치와 미설정 데이터는 유지했다.

### 변경-034: 편집기 통합과 선택적 검사

사용자 결정: 관리 창을 계속 늘리지 않고 통합 가능한 항목을 묶는다. 저장 때마다 유효성 검사로 막지 말고, 더미·빈 데이터도 저장하며 원할 때만 검사한다.

| 항목 | 변경 |
| --- | --- |
| 작업창 | 아이템·장비·장비 효과·장비 등급·스탯을 한 창의 탭으로 통합 |
| 자산 관리 | Ping, 파일 이름 변경, 표시 이름·코드명 편집 보강 |
| 분류 선택 | 장비 분류 폴더로 제한. 아이템의 성능 등급은 해당 장비 목록으로 제한 |
| 장비 내부 조작 | 중첩 생성·관리 버튼 제거. 관리 탭에서 만들고 장비에서는 연결 |
| 저장 | 검사와 분리. 빈 값·미완성 데이터도 저장·생성·복제 허용 |
| 검사 | 별도 ‘검사하기’와 전체 저장 데이터 검사로 제공 |
| 유지하는 보호 | 파일 접근·이름·경로·외부 변경 충돌 확인, 실제 게임 사용 전 유효성 검사 |

기존 ‘검사 후 적용·저장’ 규칙을 대체한다. 검사 결과는 저장의 필수 조건이 아니다. 시험 장면 자동 복제·열기는 다시 추가하지 않았다.

### 변경-035: 장비 효과 이름·참조 선택·스탯 표

사용자 지적: 장비 효과의 이름이 현재 역할과 맞지 않고, 원형 선택 버튼에서 자산을 더블클릭해도 등급 효과가 들어가지 않는다. 참조 메뉴와 여러 줄 스탯 입력도 혼동을 준다.

- EquipmentFixedStatEffectData를 EquipmentStatEffectData로 변경하고 스크립트 GUID를 보존했다. 기존 사용자 자산의 파일 이름은 자동 일괄 변경하지 않았다.
- 등급 효과 참조를 먼저 초안에 반영한 뒤 스탯 영역만 다시 그리도록 수정했다. 객체 선택 중 입력 필드 자체가 교체되는 경로를 분리했다.
- 등급별 입력을 ‘사용 | 스탯 | 기본값 | 값 변경 | 최종’ 표로 정리했다. 체크 해제는 ‘제외’, 재정의 해제는 공유값을 표시한다.
- 입력 필드 옆 ‘…’ 참조 열기·별도 복제 메뉴를 제거했다. 별도 참조·사용처 화면과 분류의 Ping·편집은 유지한다.

상태: 코드 수정·Unity 컴파일 오류 0개 확인. 실제 더블클릭·저장·실행 취소와 화면 가독성은 사용자 확인 대기다. 이 수정은 편집기 참조 선택 문제에 대한 것으로, 장착 기능을 새로 구현한 것은 아니다.

### 변경-036: 기획서 일괄 갱신과 문장 정리

사용자의 최종 갱신 요청에 따라 변경-031~035를 반영했다. 반복된 승인 설명·버전별 장문 기록·주관적 평가 점수를 줄이고, 문서를 게임 규칙·개발 상태·변경 사유·코드 구조로 나눴다.

폐기된 직접 확보·클리어 추가 보상·검사 필수 저장 규칙을 현행 규칙에서 제거했다. 기존 후보는 미채택 상태로 아래에 모았다. 코드·장면·자산을 수정하거나 새 기능을 승인한 작업은 아니다.

## 미채택 후보

아래 내용은 아이디어 보존용이다. 기본 게임 규칙이나 현재 개발 승인 범위가 아니다.

### 전장 재건

한 맵의 복구 부지에서 다리와 보급소를 비교한다. 다리는 아군 이동 시간을 줄이고 보급소는 범위 지원을 제공하는 안이다. 첫 승리 뒤 해금, 첫 선택·전투 밖 변경은 무료인 시험안을 검토했다. 지원 효과·영구 비용 여부는 미정이다.

시설은 다음 출전부터 적용하고 맵·부지·선택을 저장하는 안이다. 최소 비교 범위는 맵 1개·시설 2개·편성 2개다. 한 시설만 정답이 되거나 제작 부담이 크면 시각적 복구만 남기거나 보류한다.

### 계승 원정

장기 성장 정체가 확인된 뒤 환생형 반복을 원하는지 결정한다. 지역 묶음 돌파 후 사용자가 원정을 재편하고 대표 전술 하나를 계승하는 안이다.

| 유지 후보 | 초기화 후보 |
| --- | --- |
| 지역 접근·클래스/특성 해금·클래스 훈련·훈련 재료·계승 점수·재건·사용자 설정 | 공통 전력 연구·연구 재료·현재 원정 위협 진행·진행 중 전투 |

한 맵 선택은 원정과 무관하게 새 출전에서 초기화한다. 계승 보상 계산식은 미정이며 같은 달성 기록을 반복 지급에 쓰지 않는다. 이 후보를 채택해도 클리어 추가 보상이 자동으로 되살아나는 것은 아니다.

재편 전후에 잃는 값·남는 값·보상을 보여주고, 보상과 초기화를 한 저장 단위로 처리해야 한다. 대안은 초기화 없이 상위 위협·연구 상한을 확장하거나 별도 도전 모드를 만드는 것이다.

### 협동 전술

둔화된 적에 특정 공격이 명중하면 추가 관통하는 식의 조합 후보다. 같은 공격에서 재귀 발동하지 않도록 하며 해금·발동 조건·효과 수치는 미정이다. 사거리 겹침과 편성이 실제 선택을 만드는지 확인한 뒤 채택한다.

### 전술 계약

승리한 맵에서 추가 제약과 보상을 출전 전에 선택하는 안이다. 빠른 적 추가 등을 비교하되, 없는 기능을 제한 조건으로 만들지 않는다. 계약 없는 출전도 허용하는 후보이며 위협 강화와의 중복·실패 보상·수익을 먼저 검토한다.

### 신병 전수

새 클래스가 성장 격차 때문에 쓰이지 않을 때 첫 특성을 무료 또는 낮은 비용으로 제공하는 안이다. 공통 성장만으로 해결되는지 먼저 보고, 기존 클래스 소급 지급·투자 가치·중복 지급 규칙을 정한다.

### 파밍·콘텐츠 후보

- 맵별 주요 재료를 달리해 목표 보상에 따라 출전지를 고른다.
- 안전한 강화와 추가 정예의 보상 기회를 비교한다.
- 클래스 성장으로 전투 선택 후보를 해금한다. 후보 증가가 원하는 빌드를 오히려 어렵게 만들지 확인한다.
- 옆길의 별도 수색 지점에 전력을 보내는 안은 미채택이다. 폐기한 특별 전리품 직접 확보와 함께 자동 채택하지 않는다.
- 외형·공격 연출 해금, 별도 영웅·지원 주문, 개체 구매 강화·판매/철수는 채택 여부부터 결정한다.

과거 연구 배율·비용표와 체험판·출시의 맵/클래스 수는 비교용 초안이다. 현행 경제나 제작 수량으로 사용하지 않는다.
