# Project T — 신규 콘텐츠 및 주요 변경 기획서

작성일: 2026-09-15 · 수정일: 2026-09-18 · 문서 버전: 0.12 · 상태: SWUtils 코드 정리·Tangy TD 첨부 기준 표시 확대 반영, 편집 33개·플레이 25개 통과, 후속 콘텐츠 구현 대기

기준 문서: [전체 세부 기획서](01_전체세부_기획서.md) · 실행 관리: [개발 체크 기획서](02_개발체크_기획서.md)

## 1. 문서 목적

개발 중 새로운 콘텐츠가 떠오르거나, 기존 설계를 크게 바꿔야 할 때 이유·규칙·영향·검증·결정을 한곳에 기록한다. 일감 목록과 변경 이력을 혼동하지 않는다. 이 문서의 후보를 등록했다고 구현하거나 채택한 것은 아니다.

**핵심 방향이 채택된 기록은 변경-001·007·008·009·010·011·013·014·015·016·017·018·019·020·021·022의 16건이다.** 전체 게임 구현 완료를 뜻하지 않는다. 변경-020은 고정 생성 위치 구매를 직접 위치 배치로 교체하고, 변경-021은 사용자 자산과 프로젝트 구조를 정리하며, 변경-022는 1920 × 1080 기준 월드 표시를 확대한다. 공방 공격·휴식은 구현되었으며 장비·특별 전리품·위협 강화·공방 연금·스킬 빌드는 구현 대기다. 실제 실행 증거는 개발 체크 기획서에서 관리한다.

## 2. 세 문서의 관계

| 문서 | 유지할 내용 | 이 문서와의 관계 |
| --- | --- | --- |
| 전체 세부 기획서 | 현재 확정 규칙과 명확히 표시된 검토안 | 채택한 변경을 읽기 쉬운 현재 규칙으로 반영 |
| 개발 체크 기획서 | 작업·선행 조건·완료 기준·실제 진행 | 변경에 필요한 구현·검증 항목 추가 또는 수정 |
| 신규 콘텐츠 및 주요 변경 기획서 | 왜 바꾸는지, 어떤 안을 비교했는지, 영향과 결정 | 결정 근거와 과거 규칙을 보관 |

독자는 전체 기획서만 읽어도 현재 규칙을 이해해야 한다. 변경 문서를 뒤져야만 현재 규칙을 복원할 수 있는 상태로 만들지 않는다.

## 3. 등록 기준과 절차

### 3.1 이 문서에 등록할 변화

- 방어 방식, 적 경로, 배치, 승패, 직접 조작 범위가 바뀌는 경우.
- 새 클래스·맵 기믹·우두머리 행동·성장 축을 추가하는 경우.
- 공통·클래스 성장의 소유 단위나 적용 범위가 달라지는 경우.
- 재화 종류, 획득·소비·초기화 규칙, 저장 형식이 바뀌는 경우.
- 환생·미접속 보상·자동 반복 등 플레이 구조를 바꾸는 경우.
- 목표 플랫폼·판매 방식·체험판·출시 범위가 바뀌는 경우.
- 새로운 패키지 도입이 기존 구조·작업량·시각 기준을 바꾸는 경우.

설명 오타 수정이나 이미 확정한 규칙에 맞추는 단순 오류 수정은 개발 기록으로 충분하다. 수치 한 개 수정이라도 성장 시간·상위 위협·재화 가치에 큰 영향을 주면 주요 변경으로 기록한다.

### 3.2 상태 흐름

```text
제안 → 영향 분석 → 결정 대기 → 채택 → 구현 → 검증 → 문서 반영 완료
                          ↘ 보류 / 기각
검증 실패 → 수정안 작성 → 영향 분석 또는 결정 대기로 복귀
```

채택은 기획 방향에 대한 결정이고, 구현·검증 완료와 다르다. 선택에 영향을 주는 새 사실이 생기면 기존 채택 범위를 넘어 임의로 확장하지 않고 질문한다.

### 3.3 운영 순서

1. 현재 겪는 문제나 얻고 싶은 플레이 경험을 한 문장으로 적는다.
2. 현행 규칙이 확정인지 제안인지 확인한다.
3. 최소 변경안과 대안을 비교한다. 기능을 늘리는 것 외에 제거·단순화도 비교할 수 있다.
4. 전투·성장·경제·저장·화면·에셋·제작 범위의 영향을 적는다.
5. 작은 검증 방법과 채택·철회 조건을 적는다.
6. 사용자 판단이 필요한 사항을 구체적인 선택으로 질문한다.
7. 채택된 범위를 전체 기획서와 개발 체크에 연결한다.
8. 실제 구현·검증 결과를 기록하고 변경 후 규칙을 기준 문서에 정리한다.

큰 변화는 적용 전의 저장과 정의 데이터를 구분해 복구 가능하게 한다. 실제 파일 이동·삭제·저장 초기화는 그 작업의 명시된 범위를 확인한 뒤 수행한다.

## 6. 변경-001 — 공통 인크리멘탈과 클래스 성장

분류: 초기 성장 구조 확정 · 기준 변경: 0.1 → 0.2 · 상태: 핵심 방향 채택·문서 반영, 세부 규칙 협의 중

관련: 전체 기획서 6·9·10절, 결정-001~003, 개발 체크 기획-001·002, 성장-001~005.

### 6.1 사용자 결정

사용자 답변: 혼합형이며 다양한 맵과 파밍의 재미가 있어야 한다. 성장은 공통 인크리멘탈과 클래스별 단위로 진행하고, 파밍을 강화하는 뱀서라이크식 선택지를 둔다.

이 답변으로 성장 중심성과 소유 단위가 확정되었다. 클래스별 성장 비용·수치·전문화 규칙과 기존 코드의 재사용을 모두 승인한 것은 아니다.

### 6.2 이전과 이후

| 항목 | 0.1 | 0.2 |
| --- | --- | --- |
| 성장 방향 | 전략·성장·혼합 비교 | 혼합형 확정 |
| 영구 성장 단위 | 공통만 / 클래스별 / 고유 개체별 비교 | 공통 + 클래스별 확정 |
| 파밍 | 반복 성장의 수단 후보 | 다양한 맵을 도는 핵심 재미 |
| 선택 성장 | 별도 확정 없음 | 뱀서라이크식 선택 포함, 수명은 변경-008 |
| 개체별 전투 구매 강화 | 1~3단계 기본 제안 | 별도 채택 여부를 확인할 보조 후보 |

### 6.3 적용 방향과 미정 사항

공통 성장은 클래스 전체에 적용하고 클래스 성장은 같은 클래스의 캐릭터에 공유하는 기준으로 정리한다. 같은 클래스의 복수 배치는 후속 답변으로 허용했다.

클래스 성장으로 선택 후보를 해금하고 해당 맵에서 고른 효과만 활성화하는 조합을 추천 후보로 둔다. 클래스의 영구 능력 증가와 한 맵 선택 효과가 중복 적용되지 않도록 한다.

미정: 성장 재료의 개수와 이름, 공용 지급과 클래스별 획득의 관계, 수치 곡선, 클래스 수, 동시 배치 수, 초기 편성, 개체별 구매 강화.

| 저장 | 공통·클래스 누적 진행과 한 맵 선택을 분리 |

| SWUtils | 공용 정의·소유자별 진행과 효과 연결 재사용 검토 |
| 기존 코드 | 지갑·성장·마법 연결의 적합성 조사 필요 |

같은 맵·위협에서 배치·연구·선택을 한 번에 하나씩 바꾸어 결과를 비교한다. 여러 캐릭터가 같은 클래스 연구를 적용받더라도 영구 성장값 자체가 개체 수만큼 증가하면 안 된다.

사용자 결정일: 2026-09-15. 문서 반영: 전체 기획서 9절, 개발 체크 성장 단계. 구현·저장 이관·실행 검증: 미수행.

## 7. 변경-002 — 전장 재건

분류: 신규 콘텐츠·영구 맵 변화 · 대상 버전: 0.2 · 상태: 자유 배치에 맞춰 수정한 제안

관련: 전체 기획서 아이디어 2, 8·11·14절, 결정-012, 개발 체크 체험-003.

### 7.1 원하는 경험과 최소 규칙

이전 승리와 성장이 지도의 외형과 다음 전투의 선택으로 남게 한다. 현재 기본 전투안에는 재건 규칙이 들어 있지 않다.

| 항목 | 첫 검증안 |
| --- | --- |
| 대상 | 초원 맵의 복구 부지 하나 |
| 진입 | 해당 맵 최초 승리 후 해금 |
| 선택 | 다리 복구: 캐릭터 이동 경로 단축 / 보급소: 범위 내 지원 효과 후보 |
| 비용 | 첫 복구는 무료 선택. 전용 재화 추가 여부는 보류 |
| 적용 시점 | 다음 출전 준비부터 적용 |
| 변경 | 전투 밖에서 선택 변경 가능, 첫 시험은 무료 |
| 외형 | 폐허→복구된 다리·보급 시설, 바뀐 이동 가능 영역 표시 |
| 경로 | 캐릭터 경로만 변경하는 안부터 비교. 적의 우회 규칙은 별도 결정 |
| 저장 | 맵 식별자·부지 식별자·선택 시설·형식 버전 |

0.1의 고정 거점 해금·개체 강화 할인안은 자유 배치 확정에 맞춰 대체했다. 보급소의 지원 효과와 수치는 미정이다. 다리를 통한 시간 단축과 지원 효과가 다른 상황에서 각각 유리한지 비교한다.

### 7.2 플레이 전후

전: 같은 맵에 다시 가면 적 위협과 클래스 조합을 바꾼다.

후: 두 전선 사이 이동 시간을 줄이려고 다리를 복구하거나, 한 전선에 오래 머물며 지원을 받으려고 보급소를 선택한 뒤 출전한다.

### 7.3 영향과 대안

- 전투: 이동 경로와 도착 시간 또는 지원 범위가 달라진다. 보상이 같아도 선택 가치는 다를 수 있다.
- 성장: 이미 있는 공통 연구와 같은 경제 효과가 겹치는지 확인한다.
- 저장: 맵별 상태 추가. 예전 저장에 해당 항목이 없으면 미복구 상태로 간주하되 최초 승리 해금 자격은 복원한다.
- 화면: 지역 선택에서 현재 시설과 다음 전투 효과를 보여준다.
- 제작: 맵마다 시설을 여러 개 만드는 확장보다, 하나의 공통 데이터 구조로 대표 맵 한 곳을 먼저 검증한다.
- 에셋: 폐허·다리·시설·통행 표식을 실제 자산에서 확보할 수 있는지 조사한다.
- 코드: 맵 정의 원본을 변경하지 않고 저장된 선택을 출전 구성에 적용한다.

대안은 기능 효과 없는 시각적 복구다. 제작량은 작아지지만 전략 변화는 생기지 않는다. 또 다른 대안은 재건 없이 협동 전술에 집중하는 것이다.

### 7.4 검증과 철회

최소 시험: 맵 하나, 시설 선택 두 개, 동일 성장 상태, 서로 다른 편성 두 개.

관찰: 시설이 바뀔 때 배치·강화 우선순위가 실제로 달라지는가. 시설 선택 이유를 다음 전투 전에 설명할 수 있는가. 한 시설만 모든 조건에서 유리하지 않은가.

철회 조건: 고정 정답 시설이 되거나 맵 설명 부담이 전략 이익보다 크다. 미공개 검증본에서는 기능을 끄고 선택 데이터를 사용하지 않도록 할 수 있다. 공개 후 제거한다면 기록 유지·효과 대체·보상 여부를 먼저 정한다. 저장 필드를 무조건 삭제하지 않는다.

필요한 답변: 재건을 대표 차별화로 선택할지, 무료 전술 선택인지 영구 비용을 쓰는 성장인지.

사용자 결정: 미정. 구현: 미수행. 검증 결과: 없음.

## 8. 변경-003 — 계승 원정

분류: 장기 반복·초기화·경제·저장 변경 · 대상 버전: 0.2 · 상태: 보류

관련: 전체 기획서 아이디어 3, 9·14절, 결정-006, 개발 체크 출시-003·004.

### 8.1 검토 이유

장기 플레이에서 연구 상한과 전장 돌파가 멈출 때 새 원정 목표를 줄 수 있다. 아직 장기 정체가 관찰된 것은 아니다. 인크리멘탈 장르라는 이유만으로 환생이 필요하다고 판단하지 않는다.

### 8.2 후보 규칙

- 정해진 지역 묶음의 첫 돌파 후 원정 재편을 해금한다.
- 재편은 이용자가 직접 선택하며 선택 전 유지·초기화·보상 결과를 보여준다.
- 계승 대상으로 클래스 대표 전술 하나를 선택한다.
- 해금한 지역 접근은 유지하고, 이번 원정의 공세·위협 돌파 기록을 다시 쌓는 안을 먼저 비교한다.
- 원정 재편 보상은 달성한 위협 기준의 계승 점수다. 계산식은 미정이다.
- 같은 달성 기록을 재편에 여러 번 사용해 계승 점수를 반복 획득할 수 없게 한다.

### 8.3 유지·초기화 비교표

아래 표 역시 후보안이다. 이 내용을 기존 저장에 적용할 권한이나 완료 상태를 뜻하지 않는다.

| 항목 | 후보 처리 | 결정 이유·추가 검토 |
| --- | --- | --- |
| 해금된 지역 접근 | 유지 | 초반 지역을 모두 다시 해금하는 반복을 줄임 |
| 해금된 클래스·대표 특성 | 유지 | 조합 선택권 보존 |
| 클래스 훈련 단계 | 유지 | 별도로 키운 개별 성장 상실 부담 줄임 |
| 공통 전력 연구 | 초기화 후보 | 다시 빠르게 성장할 축 마련, 상실감 검증 필수 |
| 연구 결정 | 초기화 후보 | 재편 직후 기존 재화로 원상복귀하는 흐름 방지 |
| 훈련 기록 | 유지 후보 | 클래스 성장이 원정과 독립적이라는 기준 유지 |
| 계승 점수 | 유지 | 원정 간 성장 축 |
| 전투 진행·배치 개체 | 제거 | 새 원정을 진행 중 전투와 분리 |
| 한 맵 선택 효과 | 새 맵 출전 시 초기화 | 원정 여부와 무관하게 확정된 한 맵 수명 준수 |
| 현재 원정 위협 돌파 | 초기화 후보 | 재도전 목표 제공 |
| 계정 전체 최초 승리 기록 | 유지 | 원정 재편으로 최초 보상을 다시 받지 않음 |
| 재건 시설 | 유지 후보 | 지도에 남는 성장이라는 의미 보존 |
| 소리·화면·조작 설정 | 유지 | 이용자 환경 설정 |

원정 단위 보상을 별도로 반복 지급하려면 계정 최초 보상과 명칭·지급 기록을 분리해야 한다. 전체 기획서의 최초 승리 규칙을 묵시적으로 바꾸지 않는다.

### 8.4 영향·위험·대안

- 경제: 공통 연구 비용, 계승 배율, 위협 보상, 유지되는 클래스 효과가 함께 작동한다. 새 배율 하나로 끝나는 변경이 아니다.
- 전투: 낮은 위협은 빠르게 지나갈 수 있어도 준비·공세 대기 시간이 길면 재편이 지루하다.
- 저장: 재편 보상과 초기화 결과를 하나의 거래로 처리한다. 중단 시 이전 원정 또는 완료된 새 원정 중 하나로 복원되어야 한다.
- 화면: 재편 전후 예상 전력, 잃는 값, 남는 값, 새 목표를 보여줘야 한다.
- SWUtils: 영구 노드 유지 초기화 기능이 있지만 지갑·맵·보상 장부까지 자동으로 처리하지 않는다. 게임 단위 거래 설계가 필요하다.
- 범위: 계승 전용 재화·메뉴·설명·보상 균형이 추가된다.

대안은 초기화 없이 위협과 연구 상한만 확장하는 방식이다. 또 다른 대안은 별도 도전 모드에서 임시 성장을 시작하고 영구 진행은 그대로 두는 방식이다.

### 8.5 최소 검증과 결정 조건

실제 기존 저장을 초기화하기 전에, 독립 저장 사본과 계산표로 재편 전후의 성장 간격을 비교한다. 다음을 확인한다.

1. 무엇을 잃고 무엇을 얻는지 이용자가 정확히 이해한다.
2. 재편 후 이전 최고 지점까지 돌아가는 시간이 수용 가능하다.
3. 이전과 다른 편성 또는 특성 선택을 할 동기가 있다.
4. 같은 재편 거래가 재호출되어도 점수를 중복 지급하지 않는다.
5. 재편 중 저장 실패·종료 시 상태 일부만 초기화되지 않는다.

기능 제거 시 계승 재화와 연구를 어떻게 대체할지까지 정하기 전에는 공개 버전 저장에 적용하지 않는다.

필요한 답변: 초기화형 반복을 원하는지, 어떤 성장이 사라져도 괜찮은지, 재돌파의 목표 길이.

사용자 결정: 미정. 구현: 미수행. 검증 결과: 없음.

## 9. 나머지 후보의 최소 검토 메모

### 변경-004 — 협동 전술

- 문제 후보: 클래스 조합이 서로 독립 공격의 합으로만 느껴진다.
- 최소 규칙: 둔화된 적에 특정 궁수 특성이 명중하면 추가 관통. 원본 공격 한 번당 한 번만 발동하며 추가 타격으로 같은 반응을 재발동하지 않는다.
- 추가 결정: 별도 해금인지 기존 전문화인지, 발동 확률 또는 확정 조건, 피해·관통 값.
- 영향: 상태 효과 출처, 반응 우선순위, 재귀 방지, 효과 설명, 대량 전투 성능.
- 검증: 같은 두 클래스의 사거리 겹침 위치를 바꾸었을 때 결과와 이해가 달라지는가.
- 철회 조건: 조합이 없으면 진행 불가능하거나 효과 원인을 설명할 수 없다.
- 구현 전에는 공통 양식으로 전체 상세 규칙을 작성하고 결정-012와 연결한다.

### 변경-005 — 전술 계약

- 문제 후보: 같은 맵을 연구 재료 때문에 반복하는 동안 선택이 줄어든다.
- 최소 규칙: 이미 승리한 맵에서 계약 하나 선택, 출전 전에 추가 적 규칙과 보상 표시. 계약 없는 출전도 가능.
- 후보: 빠른 적 추가, 지원 주문 제한. 주문이 없는 기본안에는 주문 제한 계약을 만들지 않는다.
- 추가 결정: 위협 단계와의 중첩, 추가 보상량, 실패 보상 적용 범위, 최소 해금 조건.
- 영향: 결과 장부·최초 승리와 계약 완료 기록을 혼동하지 않도록 분리.
- 검증: 계약 없는 전투보다 시간당 수익과 체감 난도가 납득 가능하고 항상 같은 계약만 선택하지 않는가.
- 철회 조건: 성장 효율 때문에 원치 않는 제약을 필수로 선택한다.

### 변경-006 — 신병 전수 보너스

- 문제 후보: 새 클래스가 기존 훈련 단계보다 낮아 해금 후에도 편성되지 않는다.
- 현재 확정 방향: 공통 인크리멘탈과 클래스별 성장. 재료를 클래스에 자유 배분하는 방식은 아직 제안이다.
- 최소 변경: 위 기본안으로 충분한지 먼저 측정. 부족할 경우 새 클래스의 첫 특성만 무료 또는 낮은 비용으로 제공하는 안을 비교한다.
- 추가 결정: 어떤 진행 조건에서 주는지, 이미 보유한 클래스와 소급 지급을 어떻게 처리하는지.
- 영향: 기존 지불 비용과 무료 지급 기록의 구분, 환불 악용 방지, 표시 설명.
- 검증: 신규 클래스 해금 후 첫 유효 조합까지 걸리는 전투 수와 실제 사용 이유.
- 철회 조건: 기존 훈련 투자 의미를 약화시키면서 사용률을 개선하지 못한다.

### 9.1 변경-007 — 자유 배치와 이동속도에 따른 실제 이동

이 절은 당시 결정 기록이다. 이후 확정한 목적지 구매·이동 중 공격과 저지 중단·부활·첫 스테이지 수치는 9.5절이 우선한다.

분류: 전투·배치·이동 규칙 변경 · 기준 변경: 0.1 → 0.2 · 상태: 핵심 방향 채택·문서 반영

**사용자 결정:** 캐릭터를 원하는 위치에 배치하고 이동시킬 수 있다. 캐릭터마다 이동속도가 있고 배치 위치까지 가는 속도에 영향을 준다.

| 항목 | 이전 제안 | 현재 기준 |
| --- | --- | --- |
| 배치 위치 | 정해진 거점 하나에 캐릭터 하나 | 자유 위치 지정. 지형별 가능 영역은 결정 필요 |
| 이동 | 공세 사이 무료 거점 이동 | 실제 이동과 속도 차이 반영. 허용 시점·비용은 미정 |
| 전술 판단 | 어떤 거점을 점유할지 | 어디로 언제 이동시켜 전력을 도착시킬지 |
| 기존 검증 수량 | 배치 거점 8개 | 폐기. 편성·배치 인원으로 별도 산정 |
| 맵 재건 | 거점 추가 후보 | 캐릭터 이동 경로 개선 등으로 후보 재검토 |

미정인 사항은 생성 직후 이동, 이동 중 공격, 재배치 명령 시점, 저지 수·교전 개시·해제, 사망·부활, 구체 지형 통행 판정, 캐릭터 겹침, 인원과 실제 금액이다. 적 고정 경로와 통행 가능 지형 자유 배치는 변경-009, 지정 생성 위치와 전투 재화 구매는 변경-010으로 확정했다.

**추가 사용자 채택:** 근접 클래스만 적을 붙잡고 모든 클래스가 피격될 수 있는 구조로 확정했다. 저지와 피격은 별도 속성으로 설계한다. 저지 수·대상 선택·사망·재진입 등은 아직 미정이다. 비교 자료와 근거는 전체 기획서 3.1절에 기록했다.

영향:

- 지형에 적 경로와 캐릭터 통행 규칙이 필요하다.
- 캐릭터 이동·명령 변경·도착·교전 전환·채택 시 사망 흐름이 필요하다.
- 화면에 목적지·이동 상태·불가능한 위치의 이유를 보여준다.
- 이동속도 성장과 이동 시간을 함께 검증한다.
- 저장의 캐릭터 위치·이동·교전 상태와 경로 재개 범위를 정한다.
- 기존 배회형 적 코드를 자유 이동 명령 기능으로 그대로 간주하지 않는다.

검증: 같은 경로에서 속도 차이에 따른 도착, 장애물 우회, 목적지 재지정, 정지·배속, 같은 지점 중복 명령, 교전 중 이동을 시험한다. 저지 중인 적과 여분 적의 진행, 원거리·지원 클래스의 피격, 교전 해제 후 전선 변화를 검증한다.

되돌리기: 미공개 비교 장면과 데이터를 분리해 이동·교전안을 비교한다. 사용자 확정인 자유 배치를 자동으로 고정 거점으로 되돌리지 않는다.

사용자 결정일: 2026-09-15. 문서 반영: 전체 6·8절, 개발 체크 전투 단계. 구현·실행 검증: 미수행.

### 9.2 변경-008 — 한 맵 선택과 성장 재료·재화·해금 파밍

**사용자 결정:**

| 공통 성장 | 유지 |
| 클래스별 성장 | 유지 |

구체 미정: 선택 발생 조건, 3개 중 1개 같은 후보 수, 적용 대상, 중첩·상한, 재선택, 경험 자원, 해금 확률·확정 획득, 중복 해금 보상, 결과 정산 경계. 선택 팝업을 열 때 전투 정지는 후속 답변에서 확정했다.

영향:

- 영구 후보 해금과 한 맵 선택 효과를 분리한다.
- 후보 유효성·가중치·추첨 상태·기회당 선택 한 번을 관리한다.
- 보상 출처를 기본·선택 추가·최초·해금으로 구분한다.
- 새 출전에서 효과를 제거하되 같은 전투 이어하기에서는 재추첨으로 보상이 바뀌지 않게 한다.
- 공통·클래스·파밍 선택의 배율이 복수 캐릭터 때문에 의도 이상 중첩되지 않게 한다.
- 보상 선택을 했다는 이유로 다음 공세가 반드시 실패하거나, 공격 선택이 늘 손해가 되는지 비교한다.

최소 검증: 맵 2개, 서로 다른 목표 보상, 공통·클래스 성장, 공격·획득·위험 선택의 작은 후보 풀. 후보 수는 답변 후 확정한다.

보류·철회 기준: 의미 없는 선택 반복, 필수 획득량 선택, 보상 불명확, 저장 재시작을 통한 재추첨, 한 맵만 우월한 효율. 원인에 따라 후보·효과·분포를 수정하며 확정된 한 맵 선택 수명은 임의로 바꾸지 않는다.

사용자 결정일: 2026-09-15. 문서 반영: 전체 7·9·10·14절, 개발 체크 선택·파밍 단계. 구현·실행 검증: 미수행.

### 9.9 변경-015 — 공방 실제 공격과 라운드·승리 후 휴식

등록일: 2026-09-16 · 상태: 사용자 채택·0.9 구현 및 검증 · 연결: 전체 8.3절·결정-021~022, 개발 체크 2.9절·기획-013·전투-014~015.

**사용자 결정:** 이동식 마법 공방은 단순 통과 판정 표시가 아니라 실제 체력을 가진 방어 목표다. 적이 경로 끝에 도착하면 즉시 사라지지 않고 공방을 공격하며, 캐릭터가 뒤늦게 이동해 해당 적을 제거할 수 있다. 공방 HP가 0이 되는 순간 스테이지 실패다.

캐릭터는 기존 규칙대로 사망 위치에서 부활 대기 후 부활한다. 부활 대기 중에는 저지하지 않으므로 적이 무시하고 통과해 전선 공백이 발생한다. 별도 사망 페널티를 추가하기보다 이 공백 자체를 위험으로 사용한다.

**휴식 구간:** 각 라운드 종료 후 다음 라운드 시작 전 휴식 구간을 둔다. 플레이어는 재배치, 장비 장착/해제, 특별 전리품 회수 등 정비를 할 수 있다. 마지막 라운드를 성공한 뒤 결과 화면 전에도 최종 휴식을 두어 남은 특별 전리품을 확보할 기회를 제공한다. 실패 시에는 이미 확보 완료한 특별 전리품만 보존한다.

**0.8.1 추가 사용자 결정:**

- 휴식은 시간 제한 없이 유지하며 다음 라운드는 버튼으로 직접 시작한다.
- 휴식 중 부활 대기시간은 계속 진행한다. 살아 있는 아군과 공방의 체력은 자동 회복하지 않는다. 팝업을 열면 기존 일시정지 규칙에 따라 부활 대기도 정지한다.
- 공방 공격 중인 적은 근접 아군이 해당 적을 실제로 저지할 때만 저지 아군으로 공격 대상을 전환한다. 주변 아군 접근만으로 전환하지 않으며, 저지 아군의 이동·사망 등으로 저지가 해제되면 공방 공격을 재개한다. 공방 도착 전의 기존 대상 선정과 구분한다.

0.7의 '적 10명 통과→공방 내구도 감소→적 종결' 구현은 역사 기록으로 유지한다. **0.9에서는 0.8·0.8.1의 공방 공격과 휴식 규칙을 구현했다.** 첫 스테이지 위임 조정값은 공방 최대 체력 300, 해골의 공방 피해 10·공격 간격 1.4초다. 실제 타격 시점에 피해가 발생하며 뒤늦은 근접 저지·처치가 가능하다. 무제한 라운드 휴식의 '다음 라운드 시작'과 최종 휴식의 '결과 보기'를 연결했다. 휴식 중 공방 연금 사용 여부와 수리 효과의 채택·수치는 별도 결정 대상이다.

Unity CLI 편집 모드 27개·플레이 모드 16개가 모두 통과했다. 자연 교전으로 3라운드 방어, 실제 지형을 통한 늦은 공방 저지, 두 해상도의 휴식 화면과 결과를 확인했다. 상세 증거는 개발 체크 2.9절을 따른다. 전리품 회수·장비 관리는 해당 기능 구현 후 휴식에 연결한다.

### 9.10 변경-016 — 장비 2슬롯·영구 장비·설계도/파편 제작

등록일: 2026-09-16 · 상태: 사용자 채택·구현 대기 · 연결: 전체 8.8·9·10절·결정-023~024, 개발 체크 기획-014·장비-001~004.

**사용자 결정:** 장비는 영구적으로 보관되며 각 소환 캐릭터는 장비 슬롯 2개를 가진다. 스테이지 안에서 보유 장비를 원하는 캐릭터에게 자유롭게 장착·해제·교체할 수 있고, 효과는 해당 스테이지의 해당 개체에 적용된다. 스테이지가 끝나면 장비는 다시 영구 인벤토리로 돌아온다.

장비에는 등급이 존재한다. 획득 방식은 (1) 완제품 장비의 확률 드롭, (2) 장비 설계도 파밍, (3) 적에게서 얻는 제작 파편/재료를 모아 제작하는 세 경로를 채택한다. 정확한 등급 단계·옵션 수치·제작식·드롭 확률·분해 여부는 추후 데이터 설계에서 정한다.

같은 클래스 여러 명에게 서로 다른 장비를 주어 개체별 역할을 다르게 만들 수 있다. 장착/해제 반복으로 체력 회복·부활 가속·보상 같은 일회성 효과를 중복 발동하는 악용을 방지한다. 랜덤 접두사/접미사, 세트 효과, 거래는 현재 채택 범위가 아니다.

### 9.11 변경-017 — 위협 강화와 공방 연금

등록일: 2026-09-16 · 상태: 사용자 채택·세부 결정 대기 · 연결: 전체 10.6·10.8절·결정-026, 개발 체크 기획-016·위협-001~002·연금-001~002.

**위협 강화:** 출전 전에 플레이어가 적 공격력·이동속도 등 불리한 조건을 직접 강화하고, 그 대가로 골드·제작 파편·특별 전리품 드롭 확률 등 파밍 보상을 높인다. 위험과 보상은 같은 선택 화면에서 명시한다. 체력 증가·적 수 증가·아군 부활 지연 등은 후속 후보이며 정확한 단계·중첩·상한·배율은 데이터 단계에서 결정한다.

**공방 연금:** 이동식 마법 공방이 전투 전체의 운영·파밍 선택을 제공한다. 채택한 대표 방향은 부활 가속과 추가 전리품이며, 공방 수리·배치 재화 보조 등은 후보로 유지한다. 공방 연금은 캐릭터 공격 빌드를 만드는 뱀서라이크식 선택과 역할을 분리한다. 발생 시점·후보 수·비용·중복·유지 범위는 추후 결정한다.

위협 강화와 공방 연금이 같은 보상 배율을 중복 곱해 경제를 폭증시키지 않도록 출처별 정산 장부를 둔다.

### 9.12 변경-018 — 자동 획득과 특별 전리품 직접 확보

등록일: 2026-09-16 · 상태: 사용자 채택·구현 대기 · 연결: 전체 10.7절·결정-025, 개발 체크 기획-015·전투-016·장비-004.

**사용자 결정:** 반복적으로 많이 발생하는 보상과 희귀 드롭의 습득 방식을 나눈다.

- 자동 획득: 전투 배치 재화, 골드, 일반 성장 재료, 일반 제작 파편 등.
- 직접 확보: 완제품 장비, 희귀 설계도, 특수 제작 재료 등 특별 전리품.

특별 전리품은 적이 떨어뜨리면 전장에 실제 오브젝트로 남는다. 플레이어가 캐릭터를 선택해 해당 전리품으로 이동시키고, 도착 후 짧은 확보 행동을 완료하면 이동식 마법 공방이 자동 회수해 영구 인벤토리에 보관한다. 이동/확보 중 캐릭터는 공격과 저지를 하지 않는다.

확보 중 캐릭터가 죽거나 다른 명령을 받으면 확보를 취소하고 전리품은 바닥에 그대로 남긴다. 전리품은 짧은 시간 제한으로 자동 소멸시키지 않으며 라운드 휴식과 승리 후 최종 휴식에서 회수할 수 있다.

**핵심 보존 규칙:** 한 번 확보를 완료한 완제품 장비·설계도·특별 전리품은 이후 스테이지가 실패해도 가져간다. 확보하지 못한 전리품은 실패 시 획득하지 않는다. 이 규칙 때문에 전설/희귀 드롭을 확보하기 위해 전선을 비우는 판단과 공방 방어가 직접 경쟁한다.

넓은 전장에서 희귀 드롭을 놓치지 않도록 빛기둥·아이콘·화면 가장자리 방향 표시·짧은 알림음을 사용한다. 정확한 표현은 UI/아트 단계에서 결정한다.

### 9.13 변경-019 — 다중 고유 스킬 교체형 빌드

등록일: 2026-09-16 · 상태: 사용자 채택·세부 결정 대기 · 연결: 전체 8.7절·결정-027, 개발 체크 기획-012·전투-013.

**사용자 결정:** 캐릭터/클래스는 여러 고유 스킬을 가지며 플레이어가 직접 스킬 구성을 교체해 빌드를 만든다. 이전의 '전투 스킬 1개 + 지속 특성 1개' 추천안과 자동 사용 전제는 현재 기준이 아니다.

고유 스킬 풀은 영구 진행으로 해금될 수 있고, 실제 출전에서 장착하는 스킬 조합은 별도 상태로 관리한다. 장비 2슬롯은 개체별 역할 조정, 스킬 구성은 클래스 행동 규칙 선택, 뱀서라이크 선택은 해당 출전의 임시 빌드 변화라는 서로 다른 책임을 갖는다.

미정: 클래스별 전체 스킬 수, 동시 장착 수, 자동/직접 발동, 비용·재사용 대기·대상·범위, 휴식 중 교체 허용, 성장·설계도·선택 효과와의 연동. 구현 착수 시 이 항목을 결정한다.

### 9.14 변경-020 — 직접 위치 배치와 전장 정보 표시

등록일: 2026-09-16 · 상태: 사용자 채택·0.10 구현 및 검증 완료 · 연결: 전체 6.2~6.3·8.6절·결정-017·028, 개발 체크 2.10절.

**요청 이유:** 고정 생성 위치에서 새 아군을 찾아 다시 이동시키는 조작을 줄이고, 공방 피해·공격 가능 거리·이동 목표를 전장에서 바로 읽을 수 있게 한다.

**확정 규칙:**

- 클래스 버튼을 드래그해 통행 가능 지면에 놓거나, 버튼 클릭 후 지면 클릭으로 배치한다. 두 방식을 모두 지원한다는 사용자 답변을 반영한다.
- 미리보기는 결제하지 않는다. 배치 확정 시 그 위치에 생성하고 성공한 경우에만 한 번 결제한다. 취소·화면 밖·장애물·잔액 부족에서는 생성하지 않는다.
- 공방 위 체력바는 실제 체력과 동기화한다. 선택한 아군의 공격 범위는 실제 클래스 사거리와 일치한다.
- 오른쪽 이동 명령의 목적지는 선택한 캐릭터만 도착할 때까지 표시한다. 다시 명령하면 최신 위치로 바꾸고 부활 예약 목적지도 표시한다.
- 자동 선택 없이 생성 후 대기, 같은 클래스 복수 배치, 기존 비용·이동·교전·무료 부활 규칙은 유지한다.

**대체 관계:** 변경-010·011·013의 과거 고정 생성 위치·즉시 결제 기록은 역사 기록이다. 현재 배치 입력은 변경-020을 적용한다.

**참고 범위:** [Tangy TD 공식 소개](https://store.steampowered.com/app/2245620/Tangy_TD/)의 클래스 배치·타워 이동 방향. 드래그/클릭 세부 입력과 표시 범위는 사용자 결정에 따른 Project T 설계다.

**검증:** 실제 화면 버튼 클릭·드래그, 결제 중복 방지, 무효 위치·취소·팝업, 클래스별 사거리, 목적지 변경·선택 변경·도착·부활 예약, 공방 피해/파괴 표시를 검증했다. 편집 27개·플레이 21개 통과와 두 해상도 화면 증거는 개발 체크 2.10절을 따른다.

### 9.16 변경-022 — 1920 × 1080 기준 표시 확대와 픽셀 설정

분류: 전장 표시·배치 조정 · 사용자 요청일: 2026-09-18

사용자는 1920 × 1080 기준으로 작업 중이며 기존 요소가 너무 작다고 피드백했다. 전체 요소를 함께 키우도록 답변한 후 Tangy TD 이미지를 첨부하고 그 화면보다 아주 살짝 작은 크기를 요청했다. 이 최종 첨부 기준이 두 작품의 중간 정도라는 초기 방향과 20% 확대 시안을 대체한다. 변경-014의 작은 요소 비율을 이번 기준으로 교체한다. 첨부 원본은 `Logs/Development/2026-09-18/DisplayScaleRevision/TangyReference.png`에 보관한다.

- 카메라 월드 범위 72 × 40.5 → 48 × 27로 기존 대비 50% 확대한다. 전사 약 59픽셀, 마법사 65픽셀 높이를 적용하며 첨부 화면의 일반 캐릭터 대비 조금 작은 화면 비중을 목표로 한다. 서로 다른 그림의 외형 비율을 비교한 값으로 정밀한 동일 크기를 뜻하지 않는다.
- 내부 카메라 기준은 1536 × 864 / 단위당 32픽셀 / Pixel Snapping / Point다. 출력 및 화면 메뉴 기준은 1920 × 1080으로 유지한다. Stretch Fill이 내부 화면을 1.25배 확대하므로 엄격한 정수 배율 Pixel Perfect는 아니다. 참고 비율과 전장 전체 보기를 우선한다.
- 모든 경유점과 공방이 보이도록 경로·소품·장애물·공방 위치를 재배치한다. 원본 자산의 가져오기 설정, 캐릭터·타일 월드 크기, 이동 속도·사거리·공격·체력 수치는 유지한다. 경로가 짧아져 도착 시간은 달라질 수 있다.
- 화면 메뉴는 기존 1080 기준 크기를 유지한다. 공방 지붕과 망루가 상단 정보를 가리지 않도록 배치를 보정한다.
- 720 화면에서도 같은 구도를 유지한다. 1080과 720 모두 비정수 배율이며 픽셀의 일대일 대응 대상은 아니다. 이번 작업은 표시 비율 개선이며 성능 최적화 완료를 뜻하지 않는다.

검증 결과와 화면 비교는 개발 체크 2.12절에 기록한다.
