## 전투

### 배치와 이동

| 항목 | 확정 규칙 |
| --- | --- |
| 전장 | 적은 고정 경로를 따른다. 아군은 적의 길을 포함한 통행 가능 지형에 배치한다. 아군 배치로 적의 우회 경로를 만들지 않는다. |
| 배치 입력 | 클래스 버튼을 드래그하거나, 버튼 클릭 후 지면을 클릭한다. 지정 위치에 바로 생성한다. |
| 비용 | 위치 확정과 생성이 성공한 뒤에만 차감한다. 같은 클래스를 여러 명 배치할 수 있다. |
| 생성 직후 | 자동 선택·이동 없이 대기한다. 직접 선택하기 전에는 머리 위 화살표로 표시한다. |
| 선택·이동 | 왼쪽 클릭으로 아군 선택, 오른쪽 클릭으로 목적지 지정. 빈 땅 왼쪽 클릭은 선택 해제다. |
| 이동 중 | 공격과 저지를 중단한다. 이동속도에 따라 실제 이동하며 도착 후 교전을 재개한다. |
| 잘못된 목적지 | 명령을 거부하고 기존 목적지를 유지한다. 캐릭터끼리 밀어내지 않는다. |
| 저지·피격 | 근접 클래스만 적을 저지한다. 원거리 클래스를 포함한 모든 클래스가 피격될 수 있다. |
| 사망·부활 | 사망 자리에서 캐릭터별 대기시간 후 무료 부활한다. 대기 중에는 마지막으로 지정한 목적지를 예약할 수 있다. |

배치 미리보기는 캐릭터와 실제 사거리를 보여준다. 가능한 위치는 초록색, 장애물·재화 부족은 빨간색이다. 화면 요소 위나 화면 밖에서는 숨긴다. 잘못된 배치, 오른쪽 클릭, Escape, 전투 정지, 포커스 이탈은 미결제 배치를 취소한다. 인벤토리 열기는 전투 정지로 취급하지 않는다.

선택한 아군의 사거리와 최신 목적지를 표시한다. 정지 중 예약한 목적지도 표시하며 도착하거나 선택을 해제하면 숨긴다. 이동·부활 중에는 공격이 비활성임을 구분한다. 겹친 아군은 최근 배치한 개체를 우선 선택한다.

### 공방과 목표 선정

적은 경로 끝에서 사라지지 않고 공방을 공격한다. 실제 타격 때 공방 체력이 감소하며, 0이 되면 즉시 패배한다. 경로 도착만으로 적을 제거하거나 보상을 지급하지 않는다.

- 아군은 자신의 저지 대상을 우선 공격한다. 그 외에는 사거리 안에서 출구에 가까운 적을 선택한다.
- 공방 도착 전 적은 자신을 저지하는 아군을 우선하고, 저지가 없으면 가까운 피격 가능 아군을 공격한다.
- 공방 공격 중인 적은 근접 아군이 실제로 저지할 때만 그 아군으로 대상을 바꾼다. 저지가 풀리면 공방 공격을 재개한다.
- 이동·사망·타격 전 대상 소실은 아직 발생하지 않은 공격을 취소한다. 타격 후 회복 동작은 마친다.
- 피해는 공격 애니메이션의 타격 이벤트에 맞춘다. 풀에서 재사용된 새 생명에게 이전 공격을 적용하지 않는다.

공방은 연금솥을 실은 마차다. 사용자 제작 ArcaneWorkshop·ArcaneHealthBar를 사용한다. 피격 동작은 Hit, 선택지 알림은 Alert로 구분한다. 수리·업그레이드·이동 기능은 미정이다.

### 진행과 시간

준비 → 라운드 진행 → 라운드 휴식 → 다음 라운드 → 최종 휴식 → 승리 결과 순서다. 공방이 파괴되면 즉시 패배 결과로 전환한다.

- 휴식에는 시간 제한이 없다. 버튼으로 다음 라운드를 시작하고, 최종 휴식에서는 ‘결과 보기’를 누른다.
- 휴식 중 이동·재배치와 부활 대기는 진행한다. 살아 있는 아군과 공방은 자동 회복하지 않는다.
- 인벤토리를 열거나 장비를 변경해도 전투는 계속된다. 인벤토리 밖의 필드에서 아군을 선택할 수 있다. 아이템 집기·버리기 확인 중에는 필드 입력을 막아 조작이 겹치지 않게 한다.
- Pause 버튼으로 정지해도 아군 선택·이동 예약·장비 장착/교체/해제를 허용한다. 캐릭터마다 마지막으로 유효하게 지정한 목적지 하나를 보관하고 재개 시 이동한다. 잘못된 목적지는 기존 예약을 바꾸지 않으며 사망 중 예약은 부활 후 이동에 사용한다.
- 정지 중에는 신규 캐릭터 구매·배치와 다음 라운드 진행을 허용하지 않는다. 중첩 정지 원인이 모두 해제되어야 전투와 예약 이동을 재개한다. 선택·업그레이드 화면의 정지 방향은 유지하며 세부 조작은 각 기능 구현 시 정한다.
- 배속은 1배·2배·3배를 순환한다. 결과 확정 뒤에는 배속·재개 버튼으로 전투를 진행하지 않는다.
- 플레이어용 다시시작 버튼은 없다. 개발용 TestManager의 재시작은 유지한다.

## 능력치

**능력치는 SWStat, 보유량과 진행 상태는 별도 데이터로 관리한다.** 스탯 원본을 공유하고 유닛·공방별 실행 복제본을 사용한다. 클래스·적·스테이지에서 필요한 값은 SWStatOverride로 덮어쓴다.

| 대상 | SWStat으로 관리하는 항목 |
| --- | --- |
| 유닛 공통 7개 | 최대 체력, 공격력, 공격 속도, 이동속도, 사거리, 방어력, 회피 |
| 캐릭터 전투 보조 5개 | 치명타 확률, 치명타 피해, 생명력 흡수, 스킬 가속, 방어 관통 |
| 캐릭터 운영 3개 | 저지 수, 부활 대기시간, 배치 비용 |
| 적의 공방 공격 2개 | 공방 공격 피해, 공방 공격 간격 |
| 공방 1개 | 최대 체력 |

총 18개 정의다. 현재 체력, 아이템 수량, 재화 잔액, 레벨·경험치, 부활의 남은 시간과 전투 진행은 스탯과 분리한다. 라운드 수·적 생성 간격 같은 스테이지 구성값도 별도 설정이다.

공격 속도는 회/초이며 일반 공격의 대기시간은 역수로 계산한다. 저지 수·배치 비용은 정수 규칙을 적용하고, 양수·최소값 조건은 각 데이터에서 검사한다. 최대 체력 증가만으로 현재 체력을 자동 회복하지 않으며, 최대 체력이 감소하면 현재 체력을 새 최대값 이내로 제한한다.

아군 능력치는 **클래스 기본값 + 연구 고정값 + (클래스 기본값 × 연구 비율) + 장비** 순서로 더한다. 연구 비율은 장비로 올린 값을 포함하지 않는다.

방어력·회피는 아군과 적이 모두 가진다. 치명타·생명력 흡수·방어 관통·스킬 가속은 캐릭터만 가진다. 전투가 직접 읽는 능력치이므로 표시 전용 목록이 아닌 이름 있는 항목으로 둔다. 치명타 확률·치명타 피해·회피·생명력 흡수는 1을 100%로 표시한다.

### 피해 계산

아군과 적 사이의 기본 공격 한 번은 다음 순서로 계산한다. 공방 공격은 공방에 방어력이 없으므로 적의 공방 공격 피해를 그대로 적용한다.

| 순서 | 규칙 |
| --- | --- |
| 1. 회피 | 대상의 회피 확률로 판정한다. 0.2는 20%이며 최대 75%다. 회피하면 피해·흡수가 없다 |
| 2. 치명타 | 공격자의 치명타 확률로 판정한다. 최대 100%다. 치명타 배율은 1.5 + 치명타 피해다 |
| 3. 방어·관통 | 피해 × 100 ÷ (100 + max(0, 대상 방어력 − 공격자 방어 관통)). 방어 100이면 피해가 절반이며 0이 되지 않는다 |
| 4. 피해 적용 | 대상 체력을 줄인다. 초과 피해는 통계에서 제외한다 |
| 5. 생명력 흡수 | 실제로 줄인 체력 × 흡수율만큼 공격자를 회복한다. 최대 체력을 넘지 않고 사망 중에는 회복하지 않는다 |

확률이 0이면 판정하지 않으며, 모든 보조 능력치가 0이면 공격력을 그대로 적용한다. 적은 치명타·관통·흡수가 없는 공격자로 계산한다. 스킬 가속은 스킬 구현 때 대기시간 공식을 정하며 현재 전투에는 적용하지 않는다. 치명타·회피의 화면 연출은 미정이다.

경험치·레벨 규칙은 미정이다.

## 보상과 인벤토리

### 획득과 확률

적의 보상 목록에 재화·아이템, 수량, 획득 확률을 등록한다. 기본 지급량을 사용하거나 해당 보상 항목에서 수량을 덮어쓸 수 있다. 원본 정의에 보유량을 기록하지 않는다.

- 보상 항목은 각각 0~100% 독립 판정한다. 코인과 아이템이 동시에 당첨될 수 있으며 확률 합을 100%로 맞추지 않는다.
- 100%는 확정 지급, 0% 또는 수량 0은 미지급이다.
- 아이템 수량은 0 이상의 정수다. 잘못된 참조·수량·확률은 실제 지급 전에 검사한다.
- **스테이지 클리어 추가 보상은 사용하지 않는다.** 결과 화면을 열어도 보상을 다시 지급하지 않는다.
- 보상 요약 화면은 향후 필요 시 범위를 정한다. 요약 표시와 새 보상 지급은 구분한다.

### 특별 전리품

**일반·특별 전리품 모두 획득 시 인벤토리에 자동으로 들어간다.** 전장에 남겨 두거나 캐릭터가 이동해 확보하는 규칙은 폐기했다.

ItemData의 ‘특별 전리품’ 설정은 분류와 별개다. 특별 전리품 저장·지급에 성공하면 인벤토리 아이콘이 확대됐다가 돌아오는 DOTween 연출을 재생한다. 저장 복원·아이템 파괴·중복 지급 요청에는 재생하지 않는다. 이미 저장한 획득분은 패배해도 유지한다.

### 인벤토리 조작

- 보관 한도는 없다. 최소 36칸(6×6)을 표시하고 종류가 늘면 슬롯과 세로 스크롤을 추가한다.
- 전체·장비·설계도·소모품·재료·기타로 필터한다. 미분류 아이템은 기타로 표시한다.
- 아이템이 있는 슬롯에 마우스를 올리면 Hover Box Slice로 강조하고 InventorySlotInfo UI에서 이름·분류·수량·설명과 장비의 희귀도·성능 등급·효과를 확인한다. 빈 슬롯·집기·버리기 확인 중에는 상세를 표시하지 않는다.
- 정보 팝업의 높이는 포함된 스탯 행 수·설명 길이·판매가 영역에 맞춘다. GradeBox와 아이템 이름·희귀도 이름·스탯 수치는 ColorData·SpriteData에 연결된 희귀도 분류의 색상과 박스를 사용한다. 미등록 분류와 일반 아이템은 일반 외형을 사용한다.
- 모든 아이템과 장비에 판매 재화(CurrencyData)와 1개당 판매가를 둔다. 일반 아이템은 ItemData, 장비 아이템은 연결한 EquipmentData에서 재화와 가격을 함께 읽는다. 같은 장비의 성능 등급은 현재 같은 판매 정보를 사용한다. 가격은 0 이상의 유한한 수이며 기존 데이터의 초기값은 0이다. 재화는 코인으로 고정하거나 미연결 값을 자동 지정하지 않는다.
- 정보 팝업은 판매 재화의 아이콘과 금액을 표시하며 아이콘이 없으면 재화 이름을 표시한다. 유효한 판매 정보의 가격 0은 그대로 표시하고, 재화 미연결·잘못된 가격은 ‘-’로 표시한다. 판매가 데이터·표시와 실제 판매 거래는 별개이며, 버리기는 재화를 지급하지 않는다.
- 장비는 EquipmentData에 등록한 아이콘을 사용한다. 아이콘이 없으면 빈 아이콘으로 표시한다. 일반 아이템은 아이콘이 없을 때 이름을 대신 표시한다.
- 클릭 또는 드래그로 집으면 원래 슬롯의 아이템 표시가 사라지고 마우스 중심에 아이콘·수량이 따라온다. 별도 선택 박스 효과는 사용하지 않는다. 이때 저장 수량과 배치는 바꾸지 않는다.
- 빈 슬롯에 놓으면 이동하고, 다른 아이템이 있는 슬롯에 놓으면 두 위치를 교환한다. 원래 슬롯이나 창 안의 슬롯이 아닌 영역에 놓으면 원래 위치로 복귀한다. 분류 필터에서도 다른 분류의 숨겨진 아이템을 덮어쓰지 않는다. 집은 상태에서 스크롤할 수 있다.
- 창 밖 또는 DiscardSlot에 놓으면 버리기 확인창을 연다. 장착 가능한 CharacterHUD 장비 슬롯은 장착 대상으로 먼저 처리한다. 사용 가능한 수량 1개는 단일 화면, 2개 이상은 수량 선택 화면을 사용한다. 기본 1개부터 사용 가능한 수량까지 입력·증감·최대 선택이 가능하며 확인 전에는 수량을 바꾸지 않는다. 취소하면 원래 위치로 복귀한다.
- 우클릭·Escape는 창 이동, 파괴 확인, 아이템 집기 순서로 해당 조작을 취소한다. 놓기나 저장이 실패하면 기존 아이템과 배치를 유지한다. 취소에 사용한 우클릭은 HUD 장비 해제나 아이템 사용으로 이어지지 않는다.
- 집은 아이템이 없을 때 아이템을 우클릭하면 사용한다. 설계도는 즉시 1개를 소모해 제작법을 해금하며 성공 안내는 표시하지 않고 실패 사유만 표시한다. 사용 기능이 없는 아이템은 반응하지 않는다.
- 설계도는 버릴 수 없다. 창 밖이나 DiscardSlot에 놓으면 안내 후 원래 위치로 돌아온다.
- 슬롯 배치는 빈칸을 포함해 저장하고 다시 열기·재실행 시 복원한다. 전투 중 새 보상을 받아도 유효한 집기와 버리기 선택 수량은 유지한다. 장착 중 점유된 수량은 사용 가능한 인벤토리 수량에서 제외한다.
- 별도 조작이 없을 때 Escape는 인벤토리를 닫는다. 닫기·포커스 이탈은 임시 집기와 파괴 요청을 해제한다.
- 상단 제목을 드래그해 화면 안에서 창을 이동한다. 닫기 버튼은 이동 영역에서 제외한다. 아이템 집기·파괴 확인 중에는 창을 옮기지 않는다. 창 위치는 파일에 저장하지 않는다.

## 장비

### 희귀도와 성능 등급

희귀도는 장비 종류의 분류, 성능 등급은 같은 장비에서 얻을 수 있는 수치 차이다. 별도의 ‘스탯 등급’ 체계는 만들지 않는다. 희귀도와 성능 등급의 분류 자산은 Equipment/Categories 폴더에서 함께 관리한다.

EquipmentData에 이름·인벤토리 아이콘·희귀도·성능 등급 목록·판매 재화·판매가를 둔다. 캐릭터가 손에 들고 보이는 외형용 Sprite는 현재 범위에 없다. 등급 이름·개수·가중치·효과 수치는 사용자가 작성한다.

### 공유 효과와 등급별 스탯

EquipmentStatEffectData 하나에 공유 스탯 목록과 기본 증가량을 등록하고, 여러 등급에서 같은 효과를 연결한다. 등급마다 별도 효과 자산을 만들 필요는 없다.

| 설정 | 결과 |
| --- | --- |
| 사용 체크 해제 | 해당 스탯 제외 |
| 사용 체크, 값 변경 해제 | 공유 효과의 기본 증가량 사용 |
| 사용 체크, 값 변경 체크 | 입력한 증가량으로 교체. 기본 증가량에 더하지 않음 |

공유 효과에 등록된 스탯만 등급별로 조정한다. 별도 설정이 없는 스탯은 기본값으로 포함한다. **등급이 정해지면 체크된 스탯을 모두 포함하며, 스탯을 다시 무작위로 뽑지 않는다.** 높은 등급에서 새 스탯이 생기는 구성은 등급별 체크 설정으로 만든다.

다음은 설명용 예시이며 실제 밸런스가 아니다. 공유 효과는 공격력 +10, 공격 속도 +0.2를 가진다.

| 성능 등급 | 공격력 설정 | 공격 속도 사용 | 최종 효과 |
| --- | --- | --- | --- |
| C | 기본값 | 해제 | 공격력 +10 |
| B | 15로 변경 | 체크 | 공격력 +15, 공격 속도 +0.2 |
| A | 20으로 변경 | 체크 | 공격력 +20, 공격 속도 +0.2 |

퍼센트형 스탯의 0.05는 +5%p로 표시한다. 추가 효과 목록에 연결한 스탯 증가 효과도 장착 시 합산한다. 발동형 장비 능력의 조건·대상·수명은 미정이며, 아직 처리할 수 없는 효과가 연결된 장비는 장착을 거부하고 이유를 알린다.

### 드롭 등급 추첨

보상 획득 여부를 먼저 독립 확률로 판정한 뒤, 장비가 당첨되면 성능 등급을 가중치로 하나 선택한다.

등급 확률 = 해당 등급 가중치 ÷ 선택 가능한 등급 가중치 합계

가중치 0인 등급은 제외한다. 예를 들어 C·B·A·S 가중치를 60·25·10·5로 설정하면 각각 60%·25%·10%·5%다. 장비를 여러 개 지급하면 한 개마다 따로 등급을 추첨한다.

- 추첨 가능한 각 등급은 보관용 ItemData 하나와 정확히 연결되어야 한다. 인벤토리는 등급별 ItemData의 고정 식별자로 수량을 저장한다.
- 같은 장비·같은 성능 등급의 아이템은 합산하며 서로 다른 등급은 다른 종류로 보관한다.
- 보상 항목의 ‘성능 등급 무작위’를 끄면 연결한 ItemData의 고정 등급을 지급한다.
- 저장 재시도에는 이미 계산한 등급을 사용한다. 결과 화면·재시도로 다시 추첨하지 않는다.

### 장착과 제작

캐릭터마다 CharacterHUD에 장비 슬롯 2개를 둔다. 인벤토리를 연 채 필드의 아군을 선택하고 장비를 슬롯으로 끌어 넣어 장착한다. 이미 장비가 있으면 교체하며 이전 장비를 인벤토리에 돌려준다. 장비 슬롯 우클릭으로 해제한다. 인벤토리 열기와 장비 조작은 자동 정지하지 않으며 Pause 중에도 같은 조작을 허용한다.

- 한 캐릭터의 두 슬롯에는 같은 EquipmentData를 중복 장착할 수 없다. 성능 등급이 달라도 같은 장비로 판단한다. 같은 슬롯의 성능 등급 교체는 가능하다.
- 슬롯마다 사용 가능한 보유 장비 1개를 점유한다. 서로 다른 캐릭터는 보유 수량이 충분하면 같은 장비를 각각 사용할 수 있다. 점유된 수량은 다른 장착·버리기에 사용하지 않는다.
- 두 슬롯의 등급별 스탯과 지원하는 추가 스탯 효과를 합산해 해당 개체에만 적용한다. 교체·해제 시 이전 효과를 제거하며 원본 데이터나 다른 캐릭터의 수치는 바꾸지 않는다.
- 최대 체력이 증가해도 자동 회복하지 않고 감소하면 현재 체력을 제한한다. 장비 변경으로 사망한 캐릭터를 즉시 부활시키지 않는다. 교체 도중의 임시 수치로 현재 체력이 불필요하게 감소하지 않게 최종 합산을 적용한다.
- 잘못된 대상·장비·등급·수량·효과 또는 중복 장착은 거부하며 기존 장착을 유지한다. 실패한 집기는 인벤토리로 복귀하고 이유를 표시한다.
- 효과와 장착 상태는 현재 전투에만 유효하다. 승패 확정·재시작·전투 종료 시 점유와 효과를 해제한다. 영구 보유 수량은 장착 중에도 유지하므로 종료 후 장비가 사라지지 않는다. 진행 중 전투의 장착 상태 이어하기는 구현 범위에 포함하지 않는다.

반복 장착으로 일회성 효과를 중복 지급하지 않는다. 장비로 더한 방어·치명타 등 보조 능력치는 [피해 계산](#피해-계산)에 그대로 반영한다.

완제품 드롭, 설계도 획득, 파편·재료를 소비하는 제작을 사용한다. 분해·접두사/접미사·세트·거래는 미채택이다. 남은 결정은 [개발 체크의 장비 단계](02_개발체크_기획서.md#장비-단계의-작업-단위)에서 관리한다.

### 설계도와 제작

| 항목 | 확정 규칙 |
| --- | --- |
| 설계도 | 제작법(CraftingRecipeData)을 연결한 아이템이다. 인벤토리에서 우클릭해 1개를 소모하면 영구 해금한다 |
| 중복 방지 | 이미 배웠거나 인벤토리에 보유 중인 설계도는 다시 지급하지 않는다. 한 번의 지급에서도 최대 1개다 |
| 버리기 | 설계도는 버릴 수 없다 |
| 결과 | 제작법의 결과 장비 1개를 만든다. 성능 등급은 드롭과 같은 가중치로 추첨한다 |
| 비용 | 소울과 재료 아이템. 결과 장비 희귀도별 기본 비용(CraftingCostData)을 사용하고, 제작법에서 체크한 소울·재료만 덮어쓴다. 0이면 필요 없다 |
| 재료 | 아이템과 정수 수량. 설계도와 장비는 재료로 쓸 수 없다. 장착 중 점유된 수량은 사용하지 않는다 |
| 실패 | 미해금·재료나 소울 부족·저장 실패 시 소울·재료·결과를 바꾸지 않는다 |

제작은 소울 차감 → 재료 소비와 결과 지급(한 번의 인벤토리 저장) 순서로 처리한다. 인벤토리 저장이 실패하면 사용한 소울을 돌려준다. 제작은 거점의 제작 창에서만 하며 전투 중에는 제작하지 않는다.

## 성장·선택·스킬

| 기능 | 확정 방향 |
| --- | --- |
| 공통 성장 | 전체 캐릭터에 적용하는 영구 성장 |
| 클래스 성장 | 같은 클래스가 공유하는 영구 성장 |
| 한 맵 선택 | 공격·파밍 구성을 바꾸며 다음 출전에서 초기화 |
| 위협 강화 | 출전 전 적의 위험을 높이고 보상 증가 |
| 공방 연금 | 부활 가속·추가 전리품 등 운영 선택 |
| 고유 스킬 | 클래스별 여러 스킬 보유·교체로 빌드 구성 |

선택 화면은 팝업 정지 규칙을 따른다. **Pause 중 스킬 교체 허용은 확정했으며 스킬 기능 구현은 추후 진행한다.** 장착 수·발동·대기시간과 이동·사망·부활·휴식 중 처리는 착수 전에 정한다. 전사·마법사는 현재 기본 공격만 사용한다. 기능별 남은 결정은 [개발 체크의 이후 단계](02_개발체크_기획서.md#이후-단계의-결정-항목)에서 관리한다.

### 공통 연구

공통 성장은 **연구 트리**로 만든다. SWUtils의 SWSkillTree를 사용하며 트리는 `SWTools > Utils > Data > Skill Tree Editor`에서 노드를 끌어 배치하고 선으로 연결해 편집한다.

| 항목 | 확정 규칙 |
| --- | --- |
| 노드 | 모든 노드는 1회만 연구한다(최대 레벨 1) |
| 열림 | 선으로 이어진 앞 연구 중 **하나 이상**을 완료하면 열린다. 시작 노드는 처음부터 열려 있다 |
| 효과 | 모든 아군의 능력치를 올린다. 노드마다 고정값 또는 클래스 기본값 기준 비율을 고른다. 아군이 배치될 때 적용하며 적·공방에는 적용하지 않는다 |
| 비용 | 소울만 사용하며 노드마다 고정 가격이다 |
| 환불 | 연구 하나를 환불하면 사용한 소울을 전액 돌려받는다. 이어진 연구가 그 연구에만 의존하면 거절한다 |
| 초기화 | 「연구 초기화」로 모든 연구를 풀고 사용한 소울을 전액 돌려받는다 |
| 위치 | 거점의 연구 창에서만 연구·환불·초기화한다 |

트리 규칙(최대 레벨 1, 비용 재화 Soul)을 어긴 데이터는 연구를 막고 이유를 표시하며 게임은 연구 효과 없이 진행한다.

클래스 성장으로 전술을 해금하는 구성은 세부 설계 후보다. 같은 맵·위협의 적을 플레이어 성장에 자동 비례시키지 않는 안, 성장 후 이전 맵을 빠르게 파밍하는 안도 검토 대상으로 둔다. 과거 연구 배율·비용 예시는 확정 경제값으로 사용하지 않는다.

재건·계승 원정·협동 전술·전술 계약·신병 전수·수색은 [미채택 후보](<03_신규콘텐츠 및 주요변경_기획서.md#미채택-후보>)로 관리한다. 환생·자동 반복·전투 생략·미접속 보상은 미정이다.

## 화면

### 게임 흐름

**Bootstrap → 타이틀 → 거점 → 출전(스테이지) → 결과 → 거점**을 반복한다.

| 장면 | 역할 |
| --- | --- |
| Bootstrap | 화면 없이 공통 관리자(데이터·소울·인벤토리·풀·TestManager)를 준비하고 저장을 읽은 뒤 타이틀로 이동 |
| 타이틀 | 「게임 시작」은 거점으로, 「게임 종료」는 게임을 끈다. 저장이 하나뿐이므로 이어하기·새 게임·슬롯 선택은 두지 않는다 |
| 거점 | 출전·연구·제작·인벤토리·소울 확인 |
| 스테이지 | 전투. 결과 화면의 「거점으로 돌아가기」로 거점에 복귀 |

거점에서 타이틀로 돌아가는 버튼은 두지 않는다. 편집기에서는 어느 장면에서 Play해도 Bootstrap을 거친 뒤 Play 직전에 열려 있던 장면으로 이동한다.

| 화면 | 표시·조작 | 추가 예정 |
| --- | --- | --- |
| 타이틀 | 게임 제목, 게임 시작·게임 종료 | 설정 |
| 캐릭터 정보 | 선택 아군의 외형·체력·부활·설정 레벨/경험치, 장비 2슬롯·아이콘/희귀도·장착/교체/해제 | 경험치 획득·레벨 상승·스킬 조작 |
| 클래스 선택 | 초상화·가격, 클릭/드래그 배치 | 전체 게임 편성 방식 |
| 상단 정보 | 라운드·처치 수·전투 코인·소울 | 추가 재화 표시 |
| 하단 조작 | 인벤토리·배속 아이콘·정지 | 설정 상세 |
| 전투 진행·안내 | 진행 버튼과 안내 문구를 별도 표시 | 기능별 안내 확장 |
| 인벤토리 | 사용 가능 수량·분류·상세·판매 정보·자유 배치/교환·파괴·창 이동·획득 연출·장비 전달·설계도 우클릭 사용 | 설계도 외 아이템 사용·실제 판매 |
| 결과 | 승패·진행·공방 체력·전투 시간·영웅 목록/상세, 결과 확정 후 거점으로 돌아가기 | 필요 시 획득 내역 요약 |
| 거점 | 소울 잔액, 등록 스테이지 출전(검사 실패 스테이지는 비활성), 연구 창(트리 드래그·휠 확대, 연구 상태·효과·선행 연구·비용 상세, 연구하기·환불·연구 초기화), 제작 창(배운 설계도 목록·결과 장비·소울/재료 보유 대비 필요·제작), 인벤토리(전투와 같은 창, 전투 코인은 ‘-’) | 클래스 성장·영웅 관리·스테이지 해금 |

거점의 연구 창·제작 창·인벤토리는 한 번에 하나만 연다. 출전하면 다른 출전 버튼을 막고 장면을 전환한다. 장비 장착은 전투 중에만 한다.

결과의 전투 시간은 배속과 무관한 실제 경과 시간이다. 준비·휴식·정지를 제외한다. 개체별 목록은 실제 누적 피해와 처치를 표시하며 초과 피해를 제외한다. 처치는 마지막 타격 개체에 기록한다. 피해·처치 정렬을 지원하고 동률은 배치 순서다.

영웅 상세는 종료 시점의 레벨·경험치·13개 능력치와 공격 정보를 보여준다. 기본 공격 초당 피해량은 공격력 × 공격 속도이며 확률과 대상에 따라 달라지는 치명타·방어는 포함하지 않는다. 스킬 두 칸은 스킬이 없으면 ‘미설정’이며 가상의 피해를 더하지 않는다. 상세에서 목록으로 돌아오면 정렬·스크롤을 유지한다.

편성·설정 화면의 구체 구성은 미정이다. 빈 목록·잠금·뒤로 가기·중첩 정지는 해당 기능과 함께 결정한다.

## 데이터 편집

Project T > 데이터에서 클래스·적·스테이지·경로·재화 편집기를 연다. 아이템·장비·장비 효과·장비 등급·스탯·제작법·제작 기본 비용은 한 창의 탭으로 관리한다.

| 항목 | 규칙 |
| --- | --- |
| 공통 조작 | 검색·생성·복제·되돌리기·실행 취소·미리보기·참조와 사용처·Ping·파일 이름 변경·표시 이름 편집. SWStat·SWCategory는 코드명도 편집 |
| 스테이지 장면 | 스테이지 데이터에 거점에서 불러올 전투 장면 경로를 입력한다. 빌드 설정에 없는 경로는 검사에 실패하고 거점에서 출전할 수 없다 |
| 편집과 저장 | 일반 입력은 복사본(초안)에서 편집하고 저장 버튼으로만 원본에 반영한다. 파일 이름 변경은 즉시 반영한다 |
| 검사 | **저장과 검사하기는 별도 버튼이다.** 빈 값·미완성 데이터도 저장·생성·복제한다. 검사 규칙은 각 데이터가 가지며 사용자가 원할 때 실행한다 |
| 유지하는 보호 | 파일 이름·경로·잠금·외부 원본 충돌은 저장 때 확인한다. 실제 게임에서 데이터를 사용할 때의 유효성 검사도 유지한다 |
| 분류 선택 | 장비의 희귀도·성능 등급은 Equipment/Categories 폴더의 분류만, 아이템의 성능 등급은 연결한 장비의 등급만 고른다 |
| 참조 관리 | 분류는 해당 탭에서 만들고 장비에서는 참조만 연결한다. 입력 필드 안에서 생성·복제하지 않는다 |
| 등급별 스탯 | ‘사용 \| 스탯 \| 기본값 \| 값 변경 \| 최종’ 표에서 스탯 한 개를 한 줄로 표시한다 |
| 판매 정보 | ‘판매 재화’와 ‘판매가 (1개)’를 편집한다. 장비 아이템은 연결 장비의 값을 표시하며 장비 데이터에서 수정한다. 미리보기에 재화 이름을 함께 표시한다 |

초안 복구는 같은 Unity 세션의 창 재열기·재컴파일 범위다. Unity 종료 후 복구나 게임 저장을 대신하지 않는다. 시험 장면·데이터 자동 복제 기능은 두지 않는다.

## 저장

소울과 영구 아이템은 SWUtils의 로컬 저장을 사용한다. **저장 슬롯은 하나**이며 게임 시작은 항상 같은 진행을 이어간다. 저장 성공 후 보유량과 화면을 갱신하며 이미 지급한 식별자로 중복 지급을 막는다.

| 대상 | 저장 내용 |
| --- | --- |
| 소울 | ProjectT_Soul 슬롯, 형식 버전 1, 잔액·지급 완료 식별자 |
| 인벤토리 | ProjectT_Inventory 슬롯, 형식 버전 2, ItemData 고정 식별자별 전체 보유 수량·지급 완료 식별자·빈칸을 포함한 슬롯 배치·해금한 설계도 식별자 |
| 연구 | ProjectT_Research 슬롯, 형식 버전 1, 트리 식별자와 노드별 실제 지불 기록 |

신규 잔액은 0, 인벤토리는 빈 목록이다. 지급이 없으면 빈 저장 파일을 만들지 않는다. 손상되거나 지원하지 않는 저장을 빈 상태로 덮어쓰지 않는다. 아이템 정의를 찾지 못해도 저장 수량은 유지한다. 파일 이름·경로 변경은 자산 식별자를 유지하고 복제 자산은 다른 종류가 된다.

혼합 처치 보상은 소울 저장 → 아이템 저장 → 전투 코인 반영 순서다. 두 영구 파일을 한 번에 저장하는 구조는 아니다. 앞선 저장만 성공하면 그 결과를 유지하고 지급 기록으로 재시도 중복을 막는다. 보류 요청과 계산된 등급은 현재 전투 메모리에만 있으며 앱 종료 후 복구하지 않는다.

형식 버전 1 인벤토리 저장도 읽으며 해금 목록은 빈 상태로 시작하고 다음 저장에서 버전 2로 바뀐다. 슬롯 배치가 없는 저장은 기존 목록 순서로 배치해 읽는다. 위치 이동·교환은 수량이나 지급 기록을 바꾸지 않으며 저장에 실패하면 이전 배치를 유지한다. 장착 점유는 현재 전투 메모리에서만 관리하고 파일에는 전체 보유 수량을 유지한다. 앱을 종료해도 장비 소유권은 유지하지만 진행 중 장착 상태는 복원하지 않는다.

제작은 소울과 인벤토리 두 파일을 차례로 저장하며 뒤 저장이 실패하면 소울을 돌려준다. 연구는 소울을 먼저 저장하고 진행이 바뀐 경우에만 연구 파일을 저장한다. 연구 저장이 실패하면 안내하고 다음 변경 때 다시 저장하며, 그 사이 게임을 끄면 소울만 차감된 상태가 될 수 있다. 저장된 진행이 현재 트리와 맞지 않으면 기존 파일을 덮어쓰지 않는다. 클래스 성장, 지역·클래스 해금, 사용자 설정, 전투 이어하기는 후속 저장 범위다. 새 출전의 선택 초기화와 같은 전투 이어하기의 보존을 구분해야 한다. 자동 백업·스냅샷·클라우드는 현재 범위에 없다.

## 콘텐츠와 시각 기준

현재 콘텐츠는 초원 스테이지 1이다. 추가 지역 후보는 묘지·납골당·화산이며, 배경뿐 아니라 접근로·이동 거리·적 조합·목표 보상을 다르게 구성한다. 기본 보병·빠른 적·무리·내구형·지원형·우두머리의 수량과 고유 규칙은 해당 단계에서 정한다. 과거 체험판·출시 수량은 현행 목표가 아니다.

주요 그림은 Epic RPG World Collection을 기준으로 한다. DOTween, All In 1, Pixel Craft VFX, Flipbook VFX, Damage Numbers Pro 등 보유 자산을 필요한 역할에 사용한다. 사거리·경로·적·목적지·공방 체력을 공격 연출보다 먼저 읽을 수 있게 한다.

다국어는 **Unity Localization을 나중에 한 번에 적용**한다. 그 전까지 코드·프리팹·데이터의 한글 문구를 직접 작성하며, 적용 시 코드 안내 문구·데이터 이름과 설명·프리팹 고정 문구·연구 화면 한글화 클래스를 String Table로 옮기고 언어별 폰트를 설정한다. 지원 언어는 미정이다.

출력·Canvas 기준은 1920×1080, 월드 범위 48×27이다. Pixel Perfect Camera 내부 기준은 1536×864, 단위당 32픽셀, Orthographic Size 13.5다. 1080 출력의 1.25배 확대는 참고 화면의 크기 비율을 우선한 설정으로, 엄격한 정수 배율 픽셀 표시는 아니다.

참고 게임은 [Tangy TD](https://store.steampowered.com/app/2245620/Tangy_TD/)와 [Kingdom Rush 6: Genesis TD](https://store.steampowered.com/app/4259190/Kingdom_Rush_6_Genesis_TD/)다. 2026-09-15에 조사한 배치·이동·장비·전장 조합의 참고 기록이며, Project T의 세부 규칙은 사용자 결정에 따른다.

출시 운영체제·가격·출시일·예산·목표 플레이 시간·최대 개체 수·성능 목표는 미정이다. 실제 사용 확인에서는 배치 변화의 효과, 성장 체감, 맵별 파밍 이유, 실패 원인, 반복 조작 부담을 살핀다.
