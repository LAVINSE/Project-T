# Project T 전체 기획서

수정일: 2026-09-24 · 버전: 0.23

캐릭터를 자유롭게 배치하고 이동시키며 마법 공방을 지키는 싱글 플레이 디펜스 게임이다. 전투에서 얻은 재화와 장비로 공통·클래스 성장을 진행하고, 목표 보상에 따라 다른 맵에 출전한다. 스팀 유료 출시를 목표로 하는 1인 개발 프로젝트다.

이 문서는 게임 규칙을 다룬다. 구현 상태와 다음 작업은 [개발 체크](02_개발체크_기획서.md), 변경 사유와 미채택 아이디어는 [변경 기록](<03_신규콘텐츠 및 주요변경_기획서.md>), 코드·자산 위치는 [구조 가이드](04_프로젝트구조_가이드.md)를 따른다.

- **확정:** 사용자가 채택한 규칙. 구현 완료를 뜻하지 않는다.
- **구현:** 코드와 연결이 존재한다. 실제 사용 확인이 남은 항목은 개발 체크에 표시한다.
- **미정·후보:** 개발 전에 선택이 필요한 내용.

## 현재 범위

기본 전투, 결과 통계, 소울·아이템 저장, 인벤토리, 특별 전리품 자동 획득 연출, 장비 등급 데이터·추첨, SWStat 기반 능력치와 데이터 편집기를 구현했다.

장비 장착·제작, 영구 성장, 거점·재출전, 한 맵 선택, 위협 강화, 공방 연금, 고유 스킬은 후속 개발이다. 체험판·출시 준비는 현재 로드맵에서 제외한다. 실제 사용 검증과 콘텐츠 수치 입력은 사용자가 별도로 진행한다.

## 전투

### 배치와 이동

| 항목 | 확정 규칙 |
| --- | --- |
| 전장 | 적은 고정 경로를 따른다. 아군은 적의 길을 포함한 통행 가능 지형에 배치한다. 아군 배치로 적의 우회 경로를 만들지 않는다. |
| 배치 입력 | 클래스 버튼을 드래그하거나, 버튼 클릭 후 지면을 클릭한다. 지정 위치에 바로 생성한다. |
| 비용 | 위치 확정과 생성이 성공한 뒤에만 차감한다. 같은 클래스를 여러 명 배치할 수 있다. |
| 생성 직후 | 자동 선택·이동 없이 대기한다. 직접 선택하기 전에는 머리 위 화살표로 표시한다. |
| 선택·이동 | 왼쪽 클릭으로 아군 선택, 오른쪽 클릭으로 목적지 지정. 빈 땅 왼쪽 클릭은 선택 해제다. |
| 이동 중 | 공격과 저지를 중단한다. 이동속도에 따라 실제 이동하며 도착 후 교전을 재개한다. |
| 잘못된 목적지 | 명령을 거부하고 기존 목적지를 유지한다. 캐릭터끼리 밀어내기는 구현하지 않았다. |
| 저지·피격 | 근접 클래스만 적을 저지한다. 원거리 클래스를 포함한 모든 클래스가 피격될 수 있다. |
| 사망·부활 | 사망 자리에서 캐릭터별 대기시간 후 무료 부활한다. 대기 중에는 마지막으로 지정한 목적지를 예약할 수 있다. |

배치 미리보기는 캐릭터와 실제 사거리를 보여준다. 가능한 위치는 초록색, 장애물·재화 부족은 빨간색이다. 화면 요소 위나 화면 밖에서는 숨긴다. 잘못된 배치, 오른쪽 클릭, Escape, 팝업 진입, 포커스 이탈은 미결제 배치를 취소한다.

선택한 아군의 사거리와 최신 목적지를 표시한다. 목적지는 도착하거나 선택을 해제하면 숨긴다. 이동·부활 중에는 공격이 비활성임을 구분한다. 겹친 아군은 최근 배치한 개체를 우선 선택한다.

### 공방과 목표 선정

적은 경로 끝에서 사라지지 않고 공방을 공격한다. 실제 타격 때 공방 체력이 감소하며, 0이 되면 즉시 패배한다. 경로 도착만으로 적을 제거하거나 보상을 지급하지 않는다.

- 아군은 자신의 저지 대상을 우선 공격한다. 그 외에는 사거리 안에서 출구에 가까운 적을 선택한다.
- 공방 도착 전 적은 자신을 저지하는 아군을 우선하고, 저지가 없으면 가까운 피격 가능 아군을 공격한다.
- 공방 공격 중인 적은 근접 아군이 실제로 저지할 때만 그 아군으로 대상을 바꾼다. 저지가 풀리면 공방 공격을 재개한다.
- 이동·사망·타격 전 대상 소실은 아직 발생하지 않은 공격을 취소한다. 타격 후 회복 동작은 마친다.
- 피해는 공격 애니메이션의 타격 이벤트에 맞춘다. 풀에서 재사용된 새 생명에게 이전 공격을 적용하지 않는다.

공방은 연금솥을 실은 마차다. 사용자 제작 ArcaneWorkshop·ArcaneHealthBar를 사용한다. 피격 동작은 Hit, 선택지 알림은 Alert로 구분한다. 수리·업그레이드·이동 기능은 미정이다.

### 진행과 시간

준비 → 라운드 진행 → 라운드 휴식 → 다음 라운드 → 최종 휴식 → 승리 결과 순서다. 공방이 파괴되면 즉시 패배 결과로 전환한다.

- 휴식에는 시간 제한이 없다. 버튼으로 다음 라운드를 시작하고, 최종 휴식에서는 ‘결과 보기’를 누른다.
- 휴식 중 이동·재배치와 부활 대기는 진행한다. 살아 있는 아군과 공방은 자동 회복하지 않는다.
- 인벤토리·팝업·업그레이드 화면을 열면 전투가 정지한다. 중첩 정지 원인이 모두 해제되어야 재개한다.
- 배속은 1배·2배·3배를 순환한다. 결과 확정 뒤에는 배속·재개 버튼으로 전투를 진행하지 않는다.
- 플레이어용 다시시작 버튼은 없다. 개발용 TestManager의 재시작은 유지한다.

## 능력치

**능력치는 SWStat, 보유량과 진행 상태는 별도 데이터로 관리한다.** 스탯 원본을 공유하고 유닛·공방별 실행 복제본을 사용한다. 클래스·적·스테이지에서 필요한 값은 SWStatOverride로 덮어쓴다.

| 대상 | SWStat으로 관리하는 항목 |
| --- | --- |
| 유닛 공통 5개 | 최대 체력, 공격력, 공격 속도, 이동속도, 사거리 |
| 캐릭터 추가 7개 | 방어력, 치명타 확률, 치명타 피해, 회피, 생명력 흡수, 스킬 가속, 방어 관통 |
| 캐릭터 운영 3개 | 저지 수, 부활 대기시간, 배치 비용 |
| 적의 공방 공격 2개 | 공방 공격 피해, 공방 공격 간격 |
| 공방 1개 | 최대 체력 |

총 18개 정의다. 현재 체력, 아이템 수량, 재화 잔액, 레벨·경험치, 부활의 남은 시간과 전투 진행은 스탯과 분리한다. 라운드 수·적 생성 간격 같은 스테이지 구성값도 별도 설정이다.

공격 속도는 회/초이며 일반 공격의 대기시간은 역수로 계산한다. 저지 수·배치 비용은 정수 규칙을 적용하고, 양수·최소값 조건은 각 데이터에서 검사한다. 최대 체력 증가만으로 현재 체력을 자동 회복하지 않으며, 최대 체력이 감소하면 현재 체력을 새 최대값 이내로 제한한다.

**추가 능력치 7개는 정의·조회·표시까지 구현했다. 방어·치명타·회피 등의 전투 공식은 아직 없다.** 경험치 획득·레벨 상승·성장 저장도 후속 작업이다.

## 보상과 인벤토리

### 획득과 확률

적의 보상 목록에 재화·아이템, 수량, 획득 확률을 등록한다. 기본 지급량을 사용하거나 해당 보상 항목에서 수량을 덮어쓸 수 있다. 원본 정의에 보유량을 기록하지 않는다.

- 보상 항목은 각각 0~100% 독립 판정한다. 코인과 아이템이 동시에 당첨될 수 있으며 확률 합을 100%로 맞추지 않는다.
- 100%는 확정 지급, 0% 또는 수량 0은 미지급이다.
- 아이템 수량은 0 이상의 정수다. 잘못된 참조·수량·확률은 실제 지급 전에 검사한다.
- **스테이지 클리어 추가 보상은 사용하지 않는다.** 결과 화면을 열어도 보상을 다시 지급하지 않는다.
- 보상 요약 화면은 향후 필요 시 범위를 정한다. 요약 표시와 새 보상 지급은 구분한다.

### 특별 전리품

**일반·특별 전리품 모두 획득 시 인벤토리에 자동으로 들어간다.** 전장에 남겨 두거나 캐릭터가 이동해 확보하는 규칙은 폐기했다.

ItemData의 ‘특별 전리품’ 설정은 분류와 별개다. 특별 전리품 저장·지급에 성공하면 인벤토리 아이콘이 확대됐다가 돌아오는 DOTween 연출을 재생한다. 저장 복원·아이템 파괴·중복 지급 요청에는 재생하지 않는다. 이미 저장한 획득분은 패배해도 유지한다.

### 재화

| 종류 | 수명과 사용 |
| --- | --- |
| 전투 코인 | 매 전투의 시작 금액으로 초기화. 적 처치로 획득하고 캐릭터 배치에 사용 |
| 소울 | 획득 시 저장하는 영구 재화. 패배 후에도 유지. 현재 소비 기능 없음 |
| 영구 아이템 | 장비·설계도·소모품·재료·장비 파편·기타. 같은 ItemData별 수량 합산 |

소울과 아이템의 실제 목록·수량·드롭 확률은 사용자가 설정한다. 임의의 드롭표나 성장 비용을 확정하지 않는다. 분류만 만들었다고 설계도·포션의 사용 기능까지 구현된 것은 아니다.

### 인벤토리 조작

- 보관 한도는 없다. 최소 36칸(6×6)을 표시하고 종류가 늘면 슬롯과 세로 스크롤을 추가한다.
- 전체·장비·설계도·소모품·재료·기타로 필터한다. 미분류 아이템은 기타로 표시한다.
- 마우스를 올리면 이름·분류·수량·설명과 장비의 희귀도·성능 등급·효과를 확인한다.
- 장비는 EquipmentData에 등록한 아이콘을 사용한다. 아이콘이 없으면 빈 아이콘으로 표시한다. 일반 아이템은 아이콘이 없을 때 이름을 대신 표시한다.
- 클릭해 집거나 드래그한 아이템을 창 밖에 놓으면 파괴 확인창을 연다. 기본 1개부터 보유량까지 선택하며 확인 전에는 수량을 바꾸지 않는다.
- 창 안에 놓기·빈 슬롯 클릭은 집기를 취소한다. 우클릭·Escape는 창 이동, 파괴 확인, 아이템 집기 순서로 해당 조작을 취소한다.
- 별도 조작이 없을 때 Escape는 인벤토리를 닫는다. 닫기·포커스 이탈은 임시 집기와 파괴 요청을 해제한다.
- 상단 제목을 드래그해 화면 안에서 창을 이동한다. 닫기 버튼은 이동 영역에서 제외한다. 아이템 집기·파괴 확인 중에는 창을 옮기지 않는다. 창 위치는 파일에 저장하지 않는다.

## 장비

### 희귀도와 성능 등급

희귀도는 장비 종류의 분류, 성능 등급은 같은 장비에서 얻을 수 있는 수치 차이다. 별도의 ‘스탯 등급’ 체계는 만들지 않는다. 희귀도와 성능 등급의 분류 자산은 Equipment/Categories 폴더에서 함께 관리한다.

EquipmentData에 이름·인벤토리 아이콘·희귀도·성능 등급 목록을 둔다. 캐릭터가 손에 들고 보이는 외형용 Sprite는 현재 범위에 없다. 등급 이름·개수·가중치·효과 수치는 사용자가 작성한다.

### 공유 효과와 등급별 스탯

EquipmentStatEffectData 하나에 공유 스탯 목록과 기본 증가량을 등록하고, 여러 등급에서 같은 효과를 연결한다. 등급마다 별도 효과 자산을 만들 필요는 없다.

| 설정 | 결과 |
| --- | --- |
| 사용 체크 해제 | 해당 스탯 제외 |
| 사용 체크, 값 변경 해제 | 공유 효과의 기본 증가량 사용 |
| 사용 체크, 값 변경 체크 | 입력한 증가량으로 교체. 기본 증가량에 더하지 않음 |

공유 효과에 등록된 스탯만 등급별로 조정한다. 별도 설정이 없는 스탯은 기본값으로 포함한다. **등급이 정해지면 체크된 스탯을 모두 포함하며, 스탯을 다시 무작위로 뽑지 않는다.** 높은 등급에서 새 스탯이 생기는 구성은 등급별 체크 설정으로 만든다.

다음은 설명용 예시이며 실제 밸런스가 아니다. 공유 효과는 공격력 +10, 공격 속도 +0.2를 가진다.

| 성능 등급 | 공격력 설정 | 공격 속도 사용 | 최종 효과 |
| --- | --- | --- | --- |
| C | 기본값 | 해제 | 공격력 +10 |
| B | 15로 변경 | 체크 | 공격력 +15, 공격 속도 +0.2 |
| A | 20으로 변경 | 체크 | 공격력 +20, 공격 속도 +0.2 |

퍼센트형 스탯의 0.05는 +5%p로 표시한다. 추가 효과 목록은 향후 장비 능력을 연결할 수 있는 데이터 확장 지점이며, 능력 발동 기능은 아직 없다.

### 드롭 등급 추첨

보상 획득 여부를 먼저 독립 확률로 판정한 뒤, 장비가 당첨되면 성능 등급을 가중치로 하나 선택한다.

등급 확률 = 해당 등급 가중치 ÷ 선택 가능한 등급 가중치 합계

가중치 0인 등급은 제외한다. 예를 들어 C·B·A·S 가중치를 60·25·10·5로 설정하면 각각 60%·25%·10%·5%다. 장비를 여러 개 지급하면 한 개마다 따로 등급을 추첨한다.

- 추첨 가능한 각 등급은 보관용 ItemData 하나와 정확히 연결되어야 한다. 인벤토리는 등급별 ItemData의 고정 식별자로 수량을 저장한다.
- 같은 장비·같은 성능 등급의 아이템은 합산하며 서로 다른 등급은 다른 종류로 보관한다.
- 보상 항목의 ‘성능 등급 무작위’를 끄면 연결한 ItemData의 고정 등급을 지급한다.
- 저장 재시도에는 이미 계산한 등급을 사용한다. 결과 화면·재시도로 다시 추첨하지 않는다.

### 장착과 제작: 확정 방향, 미구현

캐릭터마다 장비 슬롯 2개를 두고 스테이지 안에서 자유롭게 장착·해제한다. 효과는 해당 스테이지의 해당 개체에만 적용하고, 종료 시 장비는 인벤토리로 돌아온다. 장비 화면은 전투를 정지한다.

현재는 장비 정의·등급별 효과 계산·표시·드롭까지 구현했다. **장착 화면과 캐릭터에 장비 효과를 적용하는 기능은 아직 없다.**

완제품 드롭, 설계도 획득, 파편·재료를 소비하는 제작을 사용한다는 방향은 확정했다. 장착 수량 점유·중복 제한, 설계도 중복 처리, 제작식·비용·제작 결과 등급은 개발 전에 결정한다. 반복 장착으로 일회성 효과를 중복 지급하지 않도록 한다. 분해·접두사/접미사·세트·거래는 미채택이다.

선택 화면은 기존 팝업 정지 규칙을 따른다. 스킬은 이동·사망·부활·휴식·정지 중 처리와 교체 시점을 함께 정한다. 현재 전사·마법사는 기본 공격만 사용한다.

공통 성장으로 전체 전력을 올리고 클래스 성장으로 전술을 해금하는 구성은 세부 설계 후보다. 같은 맵·위협의 적을 플레이어 성장에 자동 비례시키지 않는 안, 성장 후 이전 맵을 빠르게 파밍하는 안도 검토 대상으로 둔다. 과거 연구 배율·비용 예시는 확정 경제값으로 사용하지 않는다.

재건·계승 원정·협동 전술·전술 계약·신병 전수·수색은 [미채택 후보](<03_신규콘텐츠 및 주요변경_기획서.md#미채택-후보>)로 관리한다. 환생·자동 반복·전투 생략·미접속 보상은 미정이다.

결과의 전투 시간은 배속과 무관한 실제 경과 시간이다. 준비·휴식·정지를 제외한다. 개체별 목록은 실제 누적 피해와 처치를 표시하며 초과 피해를 제외한다. 처치는 마지막 타격 개체에 기록한다. 피해·처치 정렬을 지원하고 동률은 배치 순서다.

영웅 상세는 종료 시점의 레벨·경험치·13개 능력치와 공격 정보를 보여준다. 기본 공격 초당 피해량은 공격력 × 공격 속도다. 미구현 스킬 두 칸은 ‘미설정’이며 가상의 피해를 더하지 않는다. 상세에서 목록으로 돌아오면 정렬·스크롤을 유지한다.

거점 이동 버튼은 연결 대기다. 시작·이어하기·편성·설정 화면의 구체 구성은 미정이다. 빈 목록·잠금·뒤로 가기·중첩 정지는 해당 기능과 함께 결정한다.

## 데이터 편집

Project T > 데이터에서 클래스·적·스테이지·경로·재화 편집기를 연다. 아이템·장비 편집기는 아이템·장비·장비 효과·장비 등급·스탯을 한 창의 탭으로 관리한다.

- 검색·생성·복제·초안 편집·되돌리기·실행 취소·미리보기·참조와 사용처를 제공한다.
- Ping, 에셋 파일 이름 변경, 표시 이름 편집을 제공한다. SWStat·SWCategory는 코드명 등 원본 항목도 편집한다.
- **저장과 검사하기는 별도 버튼이다. 빈 값·미완성 데이터도 저장·생성·복제할 수 있다. 검사는 사용자가 원할 때 실행한다.**
- 파일 이름·경로·파일 잠금·외부 원본 충돌 같은 저장 자체의 오류는 계속 확인한다. 실제 게임에서 데이터를 사용할 때의 유효성 검사도 유지한다.
- 파일 이름 변경은 즉시 반영한다. 일반 입력은 초안에서 편집하고 저장할 때 원본에 반영한다.
- 장비의 희귀도·성능 등급 선택은 Equipment/Categories 폴더로 제한한다. 아이템의 성능 등급 선택은 연결한 장비의 등급 목록으로 제한한다.
- 장비 설정 안의 ‘새 희귀도 만들기’·‘새 성능 등급 만들기’·중복 관리 버튼은 제거했다. 생성·관리는 해당 탭에서 하고 장비에서는 참조를 연결한다.
- 입력 필드 옆 ‘…’ 참조 열기·별도 복제 메뉴는 제거했다. 별도의 참조·사용처 화면과 분류 선택의 Ping·편집은 유지한다.
- 등급 효과 선택은 참조를 먼저 반영하고 스탯 영역만 갱신하도록 수정했다. 등급별 스탯은 ‘사용 | 스탯 | 기본값 | 값 변경 | 최종’ 한 줄 표로 표시한다.

초안 복구는 같은 Unity 세션의 창 재열기·재컴파일 범위다. Unity 종료 후 복구나 게임 저장을 대신하지 않는다. 시험 장면·데이터 자동 복제 기능은 없다.

## 저장

소울과 영구 아이템은 SWUtils의 로컬 저장을 사용한다. 저장 성공 후 보유량과 화면을 갱신하며 이미 지급한 식별자로 중복 지급을 막는다.

| 대상 | 저장 내용 |
| --- | --- |
| 소울 | ProjectT_Soul 슬롯, 형식 버전 1, 잔액·지급 완료 식별자 |
| 인벤토리 | ProjectT_Inventory 슬롯, 형식 버전 1, ItemData 고정 식별자별 수량·지급 완료 식별자 |

신규 잔액은 0, 인벤토리는 빈 목록이다. 지급이 없으면 빈 저장 파일을 만들지 않는다. 손상되거나 지원하지 않는 저장을 빈 상태로 덮어쓰지 않는다. 아이템 정의를 찾지 못해도 저장 수량은 유지한다. 파일 이름·경로 변경은 자산 식별자를 유지하고 복제 자산은 다른 종류가 된다.

혼합 처치 보상은 소울 저장 → 아이템 저장 → 전투 코인 반영 순서다. 두 영구 파일을 한 번에 저장하는 구조는 아니다. 앞선 저장만 성공하면 그 결과를 유지하고 지급 기록으로 재시도 중복을 막는다. 보류 요청과 계산된 등급은 현재 전투 메모리에만 있으며 앱 종료 후 복구하지 않는다.

공통·클래스 성장, 해금, 장착·제작 거래, 사용자 설정, 전투 이어하기는 후속 저장 범위다. 새 출전의 선택 초기화와 같은 전투 이어하기의 보존을 구분해야 한다. 자동 백업·스냅샷·클라우드는 현재 범위에 없다.

## 콘텐츠와 시각 기준

현재 콘텐츠는 초원 스테이지 1이다. 추가 지역 후보는 묘지·납골당·화산이며, 배경뿐 아니라 접근로·이동 거리·적 조합·목표 보상을 다르게 구성한다. 기본 보병·빠른 적·무리·내구형·지원형·우두머리의 수량과 고유 규칙은 해당 단계에서 정한다. 과거 체험판·출시 수량은 현행 목표가 아니다.

주요 그림은 Epic RPG World Collection을 기준으로 한다. DOTween, All In 1, Pixel Craft VFX, Flipbook VFX, Damage Numbers Pro 등 보유 자산을 필요한 역할에 사용한다. 사거리·경로·적·목적지·공방 체력을 공격 연출보다 먼저 읽을 수 있게 한다.

출력·Canvas 기준은 1920×1080, 월드 범위 48×27이다. Pixel Perfect Camera 내부 기준은 1536×864, 단위당 32픽셀, Orthographic Size 13.5다. 1080 출력의 1.25배 확대는 참고 화면의 크기 비율을 우선한 설정으로, 엄격한 정수 배율 픽셀 표시는 아니다.

참고 게임은 [Tangy TD](https://store.steampowered.com/app/2245620/Tangy_TD/)와 [Kingdom Rush 6: Genesis TD](https://store.steampowered.com/app/4259190/Kingdom_Rush_6_Genesis_TD/)다. 2026-09-15에 조사한 배치·이동·장비·전장 조합의 참고 기록이며, Project T의 세부 규칙은 사용자 결정에 따른다.

출시 운영체제·가격·출시일·예산·목표 플레이 시간·최대 개체 수·성능 목표는 미정이다. 실제 사용 확인에서는 배치 변화의 효과, 성장 체감, 맵별 파밍 이유, 실패 원인, 반복 조작 부담을 살핀다.
